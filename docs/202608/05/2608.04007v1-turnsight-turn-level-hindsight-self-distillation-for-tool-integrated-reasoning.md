## 摘要
工具集成推理（Tool-Integrated Reasoning, TIR）使大型语言模型（LLMs）能够通过迭代工具交互解决复杂任务。然而，现有的强化学习方法往往依赖轨迹级监督，这限制了在长时程TIR场景中的细粒度信用分配。在策略自蒸馏通过具有特权上下文的教师分支提供更密集的信号，但现有方法通常从真实答案或检索技能中获取此类上下文，这可能无法反映智能体实际访问的状态。此外，标记级监督无法捕获工具交互的回合级结构。为解决这些问题，我们提出了TurnSight，一种回合级事后自蒸馏框架，它直接从基于执行的事后视角中获取监督。接着，它构建具有不同前视视野的多个事后视角，并通过跨视野方向一致性选择可靠的监督。最后，所选事后信号在兄弟轨迹间进行归一化，并用于自适应地调节强化学习优势，同时保留其原始优化方向。在三个基准上的广泛实验证明了TurnSight的有效性。我们的代码可在https://github.com/quchangle1/TurnSight获取。

## Abstract
Tool-Integrated Reasoning (TIR) enables LLMs to solve complex tasks through iterative tool interactions. However, existing reinforcement learning methods often rely on trajectory-level supervision, limiting fine-grained credit assignment in long-horizon TIR scenarios. On-policy self-distillation offers denser signals through teacher branches with privileged context, but existing approaches typically derive such context from ground-truth answers or retrieved skills, which may not reflect the states actually visited by the agent. Moreover, token-level supervision fails to capture the turn-level structure of tool interactions. To address this, we propose TurnSight, a turn-level hindsight self-distillation framework that derives supervision directly from execution-conditioned hindsight. It then constructs multiple hindsight views with different lookahead horizons and selects reliable supervision through cross-horizon directional agreement. Finally, the selected hindsight signal is normalized across sibling rollouts and used to adaptively modulate RL advantages while preserving their original optimization direction. Extensive experiments on three benchmarks demonstrate the effectiveness of TurnSight. Our codes are available at https://github.com/quchangle1/TurnSight.

## 一、核心问题与研究动机

- **背景**：工具集成推理（TIR）让 LLM 通过多轮“推理—调用工具—观察结果”的交互来解决复杂任务。这类多步交互带来了严重的时序信用分配问题：最终结果只能反映整条轨迹是否成功，难以判断中间哪一次工具调用是有用、冗余还是有害。
- **现有方法的不足**：
  - **轨迹级强化学习（如 GRPO）**：把同一整条轨迹的优势值平均分配给所有 token，无法区分因果贡献不同的中间工具调用。
  - **基于参考轨迹或标注的细粒度监督（如 MatchTIR）**：假设参考动作在学生策略实际访问的状态下仍然合适，但多轮工具调用会改变环境，后续状态可能偏离参考轨迹，导致监督“状态错位”。
  - **现有 on-policy 自蒸馏（OPSD）方法**：教师常依赖真实答案、参考 rollout 或检索技能等“全局信息”，不能反映当前工具交互在真实访问状态下是否恰当；且多为 token 级监督，与 TIR 的“回合（turn）”决策单元不匹配，容易在同一回合内产生互相冲突的信用信号。
- **核心问题**：如何为多轮 TIR 提供**既细粒度、又与策略实际访问状态对齐、且在交互层面保持语义一致**的监督信号。

## 二、方法论：TurnSight

### 2.1 核心思想
TurnSight 是一种**回合级事后自蒸馏（turn-level hindsight self-distillation）**框架。它直接从学生策略自身轨迹的工具执行结果中构造“事后视角”，用冻结的参考策略评估“如果看到未来工具执行结果，当前回合行为的置信度如何变化”，从而得到与状态对齐的监督信号；再用该信号调制 RL 优势值，但不改变其原始优化方向。

### 2.2 关键技术细节

**（1）执行条件的事后上下文构造**
- 对每个 turn k，以 lookahead depth d 收集未来工具调用与执行结果块：
  \(H^{(d)}_{i,k} = \{(C_{i,k}, o_{i,k}), ..., (C_{i,\bar{k}}, o_{i,\bar{k}})\}\)，其中 \(\bar{k} = \min(k+d-1, K_i)\)。
- 特权上下文：\(c^{+(d)}_{i,t} = c_{i,t} \oplus H^{(d)}_{i,k}\)，仅训练时使用。
- 教师分支使用冻结的初始参考策略 \(\pi_{ref}\)，对学生采样的 token 做 teacher-forcing，计算 token 级 log 概率差：
  \(\delta^{(d)}_{i,t} = \log \pi_{ref}(y_{i,t} | c^{+(d)}_{i,t}) - \log \pi_\theta(y_{i,t} | c_{i,t})\)。
- 正差值表示看到执行结果后教师对原 token 更自信，负差值反之。

**（2）回合级聚合**
- 将同一回合内的 token 级差距求平均，得到回合级事后信号：
  \(\bar{\delta}^{(d)}_{i,k} = \frac{1}{|Y_{i,k}|} \sum_{t \in Y_{i,k}} \delta^{(d)}_{i,t}\)。
- 避免同一回合内因格式 token、参数差异导致的信号冲突。

**（3）多前视教师选择**
- 构造多个 lookahead depth（\(D_H = \{1, 2, 3\}\)），分别对应不同时间尺度的未来依赖。
- 先对每个教师信号取方向 \(s^{(d)}_{i,k} \in \{+1, -1\}\)，用**多数投票**确定共识方向；
- 再在共识方向一致的教师中，选择**事后信号幅度最大**的教师作为最终监督：
  \(d^*_{i,k} = \arg\max_{d: s^{(d)}_{i,k}=v_{i,k}} \bar{\delta}^{(d)}_{i,k}\)。

**（4）组内归一化构造权重**
- 同一 prompt 的 16 条 rollout 作为一个组，对选中的回合级信号做组内标准化（共享均值和标准差）：
  \(\hat{\delta}_{i,k} = \frac{\bar{\delta}^*_{i,k} - \mu_{q_i}}{\sigma_{q_i} + \epsilon}\)。
- 构造有界、带符号的自适应权重：
  \(w_{i,t} = 1 + \epsilon_w \tanh(\mathrm{sign}(\hat{A}^{base}_{i,t}) \cdot \hat{\delta}_{i,k})\)，使 \(w_{i,t} \in [1-\epsilon_w, 1+\epsilon_w]\)。
- 当事后信号与基础 RL 优势方向一致时放大更新，不一致时削弱更新。

**（5）优势集成与优化目标**
- 集成优势：\(\tilde{A}_{i,t} = A^{base}_{i,t}[(1-\lambda) + \lambda w_{i,t}]\)。
- 替换 GRPO 目标中的原始优势，保留 clip 机制，训练目标为：
  \[
  J_{TurnSight}(\theta) = \mathbb{E}_{q,\{\tau_i\}}\frac{1}{G}\sum_i \frac{1}{|\tau_i|}\sum_t
  \min\big(\rho_{i,t}\tilde{A}_{i,t}, \mathrm{clip}(\rho_{i,t},1-\epsilon,1+\epsilon)\tilde{A}_{i,t}\big)
  \]
- 不引入额外的模仿目标，不依赖底层奖励构造，可与标准 policy-gradient RL 无缝集成。

## 三、实验设计

### 3.1 数据集与场景划分
- **训练数据**：FTRL 数据集，共 2,215 条训练实例，覆盖单步、多工具顺序推理、并行调用等，具备可执行环境和程序化可验证反馈。
- **评测基准**：
  - **FTRL**（in-domain）：四个测试类别（Single-Hop、Parallel Single-Hop、Multi-Hop、Parallel Multi-Hop），各 50 条；指标为 Solve-P、Solve-R、Solve-F1。
  - **BFCL**（out-of-domain）：多轮子集 Base、Missing Function、Missing Parameter、Long Context，以及 agentic 子集 Web Search、Memory；报告各子集准确率与均值。
  - **ToolHop**（out-of-domain）：995 条多跳查询、3,912 个本地可执行工具，评测代理在新工具环境下的迁移能力。

### 3.2 对比方法
- **RL 基线**：Vanilla、GRPO、ToolRL、MatchTIR（分别对应 outcome、trajectory、turn 级监督强度）。RLSD 和 TurnSight 均以 MatchTIR 作为 RL 骨干。
- **自蒸馏基线**：SDPO、RLSD、SDAR、SOD（利用特权上下文引导 RL 优化）。

### 3.3 实现细节
- 策略模型：Qwen3-4B、Qwen3-8B，从 base checkpoint 直接初始化，无中间 SFT。
- 框架：verl（HybridFlow）；每查询采样 16 条轨迹，最大 10 轮交互，训练 3 epoch。
- 超参数：\(\lambda = 0.5\)，\(\epsilon_w = 0.5\)，lookahead depths \(\{1,2,3\}\)；教师和参考分支冻结。
- 评测协议统一，同一环境与解码设置，确保结果可比。

## 六、主要结论与发现

1. **RL 有效但结果级奖励泛化差**：所有 RL 后训练方法在 FTRL 上都有提升，但 GRPO 在 BFCL、ToolHop 上明显较弱，说明结果级奖励不足以指导中间交互的信用分配。
2. **细粒度信用分配带来更强更可迁移的策略**：带回合级工具监督的方法（如 MatchTIR）显著优于 GRPO。
3. **单纯 OPSD 结合 RL 不够**：SDPO、RLSD、SDAR 虽优于 GRPO，但落后于显式回合级信用分配方法；全局特权信息在长程工具交互中难以对每个中间决策提供准确监督。
4. **TurnSight 全面最优**：在两个模型规模上均取得最佳结果；在 Qwen3-8B 上比之前最优方法平均提升 7.7%，在 Long Context、Miss Parameter 等难子集上提升尤其明显。
5. **组件贡献明确**：回合级聚合、组归一化、多教师选择均缺一不可；仅工具结果作为事后上下文最好，加入真实答案反而降低性能。
6. **全部轮次监督优于局部监督**：早期轮次监督比后期更重要，但全轨迹监督效果最佳。

## 七、优点

- **概念上直击痛点**：明确把多轮 TIR 的信用分配归纳为“状态对齐”与“交互级一致性”两个要求，动机清晰。
- **方法设计精巧**：
  - 事后监督直接从学生自己的工具执行结果构造，天然与访问状态对齐；
  - 回合级聚合避免 token 级冲突，契合 TIR 的决策粒度；
  - 多前视教师加方向一致性选择，兼顾短程质量与长程后果，避免无差别融合带来的噪声；
  - 组内归一化与有界加权，使监督信号跨轨迹可比且不会过度干扰 RL 优化方向。
- **即插即用**：不增加辅助模仿目标、不改变基础 RL 损失方向，与 GRPO 等兼容，实验中也验证了可与 MatchTIR 结合。
- **实验较规范**：统一评测协议，同时覆盖 in-domain 与 out-of-domain，基线和消融设计较全面。

## 八、不足与局限

- **模型与任务覆盖有限**：仅使用 Qwen3-4B/8B，未验证在不同模型规模、不同架构或更大模型上的表现；也未涉及需要多模态工具或代码执行等更复杂场景。
- **训练成本不透明**：未报告总训练时间、GPU 小时数，不利于复现成本评估。
- **统计显著性缺失**：未给出多次运行的标准差或显著性检验，BFCL 某些子集分数差异较小，结论稳健性有待验证。
- **对参考策略的依赖**：教师使用冻结的初始参考策略，参考策略能力较弱或与训练策略分布偏离较大时，事后信号的可靠性可能下降；论文未讨论该敏感性。
- **超参数与 FTRL 依赖**：核心超参数 \(\lambda\)、\(\epsilon_w\) 和 lookahead 深度是在 FTRL 上调出的，未验证在其他任务上的最优设置是否一致；训练与 in-domain 评测同源，存在一定的数据偏见风险。
- **方法更偏“加权”而非“新目标”**：TurnSight 只是调制 RL 优势，不改变方向，理论上无法纠正 RL 优势本身的系统性偏差；对基线的质量和奖励正确性仍有一定依赖。
