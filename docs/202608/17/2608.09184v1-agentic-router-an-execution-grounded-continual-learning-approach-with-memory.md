## 摘要
大语言模型（LLM）智能体为基于命令行的网络操作提供了一种有前景的接口，但一个看似合理的命令在执行后仍可能失败或引入操作风险。现有方法主要关注命令生成或最终配置的正确性，并未利用基于执行落地的经验来联合改进候选覆盖和动作选择。我们提出了一种面向基于CLI的SONiC操作的、基于执行落地的双路径后果感知智能体，该智能体生成多个完整动作，预测其执行后果，并通过效用与风险感知的重排序选择最终动作。提案侧路径将可复用的操作经验抽象为可检索的指导，从而在不修改提案LLM的情况下提高可行动作覆盖率；而选择侧路径通过使用真实SSH反馈的会话级LoRA更新来适应后果预测器，从而提高条件选择质量。在使用不同Qwen3提案模型的多轮SONiC操作会话上的实验表明，该框架提高了可行动作覆盖率和top-1执行成功率，并且两条适应路径在交互过程中提供了互补的增益。

## Abstract
Large language model (LLM) agents provide a promising interface for command-line-based network operations, but a plausible command may still fail or introduce operational risk after execution. Existing approaches mainly focus on command generation or final configuration correctness, and do not use execution-grounded experience to jointly improve candidate coverage and action selection. We propose an execution-grounded dual-path consequence-aware agent for CLI-based SONiC operations, which generates multiple complete actions, predicts their execution consequences, and selects the final action through utility- and risk-aware reranking. The proposal-side path abstracts reusable operational lessons into retrievable guidance to improve feasible-action coverage without modifying the proposal LLM, while the selection-side path adapts the consequence predictor through session-level LoRA updates using real SSH feedback to improve conditional selection quality. Experiments over multi-turn SONiC operation sessions with different Qwen3 proposal models show that the framework improves feasible-action coverage and top-1 execution success, and that the two adaptation paths provide complementary gains over interaction.

## 1. 论文的核心问题与整体含义（研究动机和背景）

- 随着 SONiC 等开放式可编程网络系统的发展，网络运维越来越多地依赖命令行接口（CLI）。LLM 智能体为自然语言到 CLI 操作的转换提供了可能，但**一个句法正确、语法可行的命令，在实际执行后仍可能失败或带来安全风险**。
- 举例：当只需恢复一个 BGP 对等体时，执行 `clear bgp *` 会清空所有对等体，导致路由抖动和瞬时可达性丢失。这类问题无法仅靠语言合理性判断，必须通过命令响应和执行后状态验证才能发现。
- 现有 LLM 网络自动化研究主要聚焦于意图到配置的翻译或最终配置正确性，**缺乏利用“执行落地”经验来同时改进候选生成覆盖率和动作选择质量**的机制。
- 核心研究问题可以形式化为：在多轮网络操作会话中，如何利用真实环境反馈，持续提高智能体“最终选中动作”的执行成功率（top-1 success），同时降低操作风险。
- 论文的总体含义是提出一种**基于执行反馈的双路径持续学习**框架：一条路径改进“候选覆盖”（是否有可行动作），另一条路径改进“候选选择”（可行动作是否被排到第一位）；两条路径互补，共同提升可靠、安全的 CLI 网络操作能力。

## 2. 论文提出的方法论：核心思想、关键技术细节、公式或算法流程

### 2.1 核心思想

- 将“top-1 执行失败”分解为两类不同来源：
  - **提案侧覆盖失败**：候选动作集内根本不存在可行动作，此时无论怎么重排序都无法成功。
  - **选择侧排序失败**：候选集中存在可行动作，但重排序没有将其排在首位。
- 据此设计**双路径适应机制**：
  - 提案侧：将执行中总结出的可复用操作经验存入可检索的长期记忆库，在生成候选时注入指导信息，**不修改提案 LLM**。
  - 选择侧：利用真实 SSH 反馈，以**会话级 LoRA** 微调后果预测器，改进重排序时对可行动作的条件选择质量。

### 2.2 问题建模

- 在每一轮 t，给定自然语言意图 \( q_t \)、环境观测 \( o_t \)、交互历史 \( H_{t-1} \)，决策上下文为：\( x_t = (q_t, o_t, H_{t-1}) \)。
- 提案生成器根据上下文和检索到的操作指导 \( M_t \)，生成候选动作集：
  \[
  A_t = G_{\text{prop}}(x_t, M_t) = \{ a_t^{(1)}, a_t^{(2)}, \ldots, a_t^{(K)} \}
  \]
- 后果预测器 \( f_{\theta_t} \) 对每个候选动作预测执行后果 \( \hat{z}_t^{(k)} \)：
  \[
  \hat{z}_t^{(k)} = f_{\theta_t}(x_t, a_t^{(k)})
  \]
- 通过奖励头 \( h_r \) 和风险头 \( h_\rho \) 得到奖励得分 \( \hat{r} \) 与风险得分 \( \hat{\rho} \)，按效用与风险加权排序：
  \[
  a_t^\star = \arg\max_{a_t^{(k)} \in A_t} (\hat{r}_t^{(k)} - \lambda \hat{\rho}_t^{(k)})
  \]
  其中 \( \lambda \ge 0 \) 控制风险惩罚强度。
- 选中的动作在环境中执行，得到真实后果 \( z_t^\star \) 和验证结果 \( y_t^\star \in \{0,1\} \)。
- 定义**可行动作覆盖率**指标（判断候选中是否存在可行动作）：
  \[
  c_t = \mathbb{I}[\exists a_t^{(k)} \in A_t \ \text{s.t.} \ v(x_t, \text{Exec}(a_t^{(k)})) = 1]
  \]
- 分解 top-1 成功率：
  \[
  \Pr(y_t^\star = 1) = \Pr(c_t = 1) \cdot \Pr(y_t^\star = 1 \mid c_t = 1)
  \]
  这也为双路径适应提供了理论基础。

### 2.3 双路径适应机制

#### 提案侧操作记忆（Proposal-Side Operational Memory）

- 收集执行记录后，用轻量 LLM 记忆提取器将原始成功/失败/恢复操作**抽象为结构化操作经验**，存入记忆库 \( M \)。
- 每个记忆项包含类型（type）、意图（intent）、适用条件（applicability）和可复用建议（guidance）。
- 在线检索时，将当前上下文编码为查询 \( \kappa_t \)，用文本嵌入（如 Sentence-BERT）计算余弦相似度，取相似度最高的 R 条记忆，注入提案提示词中。
- 这种方式避免修改提案 LLM，仅改变提示指导，从而提升候选覆盖。

#### 选择侧后果适应（Selection-Side Consequence Adaptation）

- 使用会话级 LoRA 对后果预测器进行低秩更新，保持基础预测器参数稳定，降低在线全量更新的风险：
  \[
  W_t = W_0 + \Delta W_t, \quad \Delta W_t = U_t V_t
  \]
- 冻结基础 LLM、奖励头和风险头，仅训练 LoRA 参数，损失函数为预测后果与真实后果之间的差异：
  \[
  \mathcal{L}_{\text{sel}} = \sum_{(x,a,z,y) \in D_t} \ell_z(f_{\theta_t}(x,a), z)
  \]
- 每一轮结束时，用本轮执行记录进行 LoRA 更新，实现持续适应。

### 2.4 算法流程

- 每轮先构建设决策上下文 \( x_t \)。
- 检索提案记忆并生成候选动作集。
- 预测每个候选动作的后果、奖励与风险，执行重排序。
- 执行 top-1 动作；若失败，则按排序继续执行后续候选动作，收集额外的执行反馈（仅用于更新，不改变 top-1 结果）。
- 用收集到的执行记录更新选择侧 LoRA 参数。
- 将记录放入记忆更新缓冲；每隔一定间隔，从缓冲中提取可复用经验并更新记忆库。

## 6. 论文的主要结论与发现

- 多候选生成能显著提高“候选集合中存在可行动作”的概率（Recall@5），**但仅有候选覆盖并不足够**，必须配合后果感知选择才能转化为更高的 top-1 执行成功率。
- 完整双路径框架在所有测试的模型规模（1.7B、8B、14B）上均取得最高的 top-1 成功率，且持续优于 no-adaptation 基线。
- 提案侧路径通过可检索经验提升候选覆盖，选择侧路径通过 LoRA 适应提升条件选择质量；两者带来的增益是**互补**的，同时启用效果最好。
- 更大规模的提案模型（如 Qwen3-14B）在绝对性能上更高，但即使是较小的 1.7B 模型，在双路径适应下也能获得明显的持续改进。
- 该框架验证了利用执行反馈做“持续学习”的可行性：在不修改提案 LLM 的前提下，通过外部记忆和轻量预测器适应就能显著改进网络自动化操作的安全性与成功率。

## 7. 优点

- **问题分解清晰**：将 top-1 失败分解为“候选覆盖失败”和“候选选择失败”，并分别给出可量化的指标（\( c_t \) 和条件 top-1 成功率），指导算法设计。
- **双路径互补设计**：提案侧用显式可检索记忆，选择侧用 LoRA 低秩适应，既保留了历史经验的可复用性，又避免了全模型在线更新的不稳定风险。
- **执行落地（execution-grounded）思想**：不依赖于语言学上的“合理”，而是以真实 SSH 命令响应和验证结果作为学习信号，更贴近实际网络运维需求。
- **轻量适应**：提案 LLM 冻结，只更新少量 LoRA 参数和维护记忆库，训练成本较低，对安全关键场景更友好。
- **考虑了风险因素**：重排序时引入风险惩罚项 \( \lambda \hat{\rho} \)，能够避免如 `clear bgp *` 这类高破坏性命令被选中。
- **实验覆盖多模型规模**，并设计了消融实验来验证各路径的具体贡献，说明论文的实证落脚点比较扎实。
