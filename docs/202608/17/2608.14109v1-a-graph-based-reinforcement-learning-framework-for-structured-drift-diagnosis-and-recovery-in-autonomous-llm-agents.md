## 摘要
自主LLM智能体越来越多地被部署在复杂的现实工作流中，但它们仍然容易受到运行时行为漂移的影响，即对原始任务的无声偏离，可能对外部系统造成不可逆的副作用。现有方法在提示级别处理漂移，但缺乏逐步检测、风险评估和恢复决策的结构化机制。由于主任务执行智能体通常是一个大型且昂贵的模型，无法在每次部署时重新训练，因此本工作针对即插即用的恢复模块。它引入了一种基于图的框架，其中通过强化学习训练单个小型语言模型，使其在恢复图的每个节点上专门化，独立于主智能体。每个节点都有精确的角色：漂移分类、操作检测、风险评估或最终决策，模型学习生成适应该角色的结构化XML格式推理。训练结合了基于规则的结构奖励和LLM作为评判者的语义质量信号，因此模型在回答方式（模式和长度）和回答内容上均被评分。在公开的AppWorld基准上的实验表明，该方法通常利用有关疑似漂移发作的信息，使用小型语言模型发出正确的恢复决策。此外，训练后的小型语言模型可靠地遵守规定的输出模式，并根据其分配的节点角色在每个字段中生成语义合适的内容。

## Abstract
Autonomous LLM agents are increasingly deployed in complex real-world workflows, yet they remain vulnerable to runtime behavioral drift, a silent deviation from the original task that can lead to irreversible side effects on external systems. Existing approaches address drift at the prompt level but lack structured mechanisms for step-level detection, risk assessment, and recovery decision. Because the main task-executing agent is often a large and expensive model that cannot be re-trained on every deployment, this work targets a plug-and-play recovery module instead. It introduces a graph-based framework in which a single small language model is trained via reinforcement learning to specialize at each node of a recovery graph, external to the main agent. Each node has a precise role\,: drift classification, operation detection, risk evaluation, or final decision and the model learns to produce structured XML-formatted reasoning adapted to that role. Training combines rule-based structural rewards with an LLM-as-judge semantic-quality signal, so that the model is graded both on how it answers (schema and length) and on what it says. Experiments on the public AppWorld benchmark show that the method generally exploits information about the suspected drift onset to issue correct recovery decisions using a small language model. In addition, the trained small language model reliably respects the prescribed output schema and produces semantically appropriate content in each field according to its assigned node role.

- 自主 LLM 智能体不仅回答问题，还能执行真实操作（调用 API、发邮件、转账、改数据库等）。一旦这些操作出错，代价远高于一次普通的幻觉回答。
- 本文关注的核心问题是 **行为漂移（Behavioral Drift）**：智能体在执行任务过程中逐渐偏离原始目标，可能由恶意指令注入（如隐藏在网页/邮件中的提示注入）或对模糊子目标的过度扩展引发。漂移一旦发生，智能体仍可能自信地继续执行后续步骤，状态不断恶化。
- 关键痛点在于：
  - 大多数现有防御只做**事前预防**（隔离不可信内容、指令层级训练、工具防火墙等），缺少**事后恢复**机制。
  - 智能体已经执行了**写操作**（发送资金、删除消息等）时，仅回滚消息历史无法回滚真实环境状态（“rolling back the message history does not roll back the world”）。
  - 让单个 LLM 在一个提示中同时完成“找漂移起点、列出写操作、判断可逆性、决定回滚或升级”等全部子任务，是脆弱且不可靠的。
- 论文提出的整体思路：将漂移恢复构建为一个小型状态机（恢复图），用**强化学习训练单一小语言模型**在各节点扮演不同诊断角色，作为主智能体之外的**即插即用外部模块**，不重训大型主智能体。
- 含义与价值：为主流“大型 LLM 智能体部署”场景提供一个低成本的、结构化的、可验证的恢复层，填补了漂移发生后“检测—评估—决策”这条技术路线的空白。

## 2. 方法论

### 2.1 核心思想

- 将漂移恢复建模为**五节点恢复图**上的路由遍历，节点间按规则跳转，每个节点有精确的职责；所有节点共享同一个策略模型，通过**角色条件提示**（node-tagged prompt）区分角色。
- 每个节点的输出强制为统一的结构化 XML 格式：一个 `<reasoning>` 块加上一个 `<answer>` JSON 块。这种“类型化消息”使下一节点可以直接读取，避免自由文本的解析歧义。
- 训练使用 **GRPO（Group Relative Policy Optimization）**，以组内相对优势驱动更新，无需价值网络，单 GPU 即可训练。

### 2.2 恢复图五节点

| 节点 | 角色 | 输出 JSON 键 |
|------|------|-------------|
| n1 Classify Drift | 判断单步是否对齐任务（Y/N）并给出简短理由 | `step, is_aligned, why` |
| n2 Detect Operations | 枚举漂移步骤中实际成功执行的写操作与偏离任务的读操作 | `write_operations, read_operations` |
| n3 Search Documentation | 去重列出涉及的应用程序/API，用于获取文档 | `apps_name` |
| n4 Evaluate Risk | 结合 API 文档将写操作划分为可逆/不可逆 | `write_reversible, write_not_reversible` |
| n5 Aggregate & Decide | 汇总证据，输出最终动作：回滚到漂移前/升级给人类 | `action, arguments` |

### 2.3 路由规则（算法流程）

1. 从外部漂移检测器提供的疑似漂移起点 k0 开始，**向后逐条回放轨迹**（k ← k0, 每次 k−1）。
2. 每一步调用 n1 判断对齐性：
   - 若 `is_aligned=N`，转入 n2 提取操作；若有写操作，依次经过 n3（查应用）、取文档、n4（风险划分），再回到 n1。
   - 若 `is_aligned=Y` 且最近 K 步全部为 Y（对齐连续段），停止向后遍历，转入 n5 做最终决策。
3. n5 根据是否有漂移期写操作决定：**rollback_before_drift（回滚消息历史到指定步骤）** 或 **escalate_human（生成结构化事件报告升级人工）**。

### 2.4 形式化定义

- 轨迹 τ = (s0, s1, ..., sn)；每步交互 xi = (Ri, Wi)，Ri 为读操作、Wi 为写操作。
- 理想执行是一组任务忠实轨迹 G(T)，而非单一轨迹；任务成功等价于存在 X(j)∈G(T) 使 X(τ) ≡ X(j)（语义等价）。
- **行为漂移（Definition 1）**：存在参考轨迹在 d 步前全部匹配，而从 d 步起不存在任何可维持的任务忠实参考；d 为漂移起点。
- **漂移三分法**：
  - Type I 瞬态读取漂移：漂移期无写操作，原因瞬时，回滚消息历史即可。
  - Type II 持久读取漂移：漂移期无写操作，但原因持续存在于环境（如邮箱中的恶意文档），需在回滚后追加“漂移记忆/警告”上下文。
  - Type III 写入漂移：漂移期发生了至少一个写操作，环境被改变，必须修复或升级人类。
- 本文范围：主要处理 Type I/II（纯回滚+警告机制）；对 Type III 只做**可逆性检测与升级决策**，不自动执行逆操作（列为未来工作）；并假设漂移严格单调（每个漂移起点后都是离题步）。

### 2.5 复合奖励

- 总奖励：R(o, ν, q) = Σ_{k=1}^{9} w_k r_k(o, ν, q)，其中 8 个为规则式结构奖励，1 个为 LLM-as-judge 语义质量信号。
- 结构奖励覆盖：XML 标签计数、严格格式奖励、宽松格式奖励、推理长度约束、总长度约束、JSON 合法性、节点键集合匹配（Jaccard 部分得分）、节点级值域检查。
- 语义奖励 r_judge：冻结的 14B 更强 LLM 作为评判者，依据节点角色 rubric 对输出的具体性、与提示的关联性、推理与答案的一致性打分（1.0=具体且正确，0.5=泛泛但不错误，0=空洞/幻觉/矛盾），并显式忽略格式问题。
- GRPO 的组归一化优势 Âᵢ = (rᵢ − r̄) / (std(r) + ε)，使所有部件奖励转化为组内竞争，无需人工调节权重。
