## 摘要
智能体技能越来越多地被用于为大型语言模型（LLM）智能体配备可重复使用的程序性知识。尽管由于技能库的不断增大，近期工作在技能检索方面取得了显著改进，但检索到一组看似合理的技能组合并不能保证执行它就是值得的。由于每次技能条件化的 rollout 在计算上都很昂贵，决定是否应执行检索到的技能组合已成为一个日益重要的挑战。为此，我们引入了奖励感知动态执行门控（RADEG），这是一个位于技能检索与智能体执行之间的轻量级、与检索器无关的决策层。RADEG 学习一个低成本的替代模型，在昂贵的 rollout 启动之前预测查询-技能组合对的执行效用。为了在控制任务难度的同时获得信息丰富的监督信号，我们通过删除、添加或替换一个技能来局部扰动每个检索到的技能组合，产生匹配的相同查询 rollout，从而隔离技能组合构成对验证器奖励的影响。在部署期间，随着新的验证器反馈变得可用，RADEG 仅更新一个热启动的逻辑回归头，使得在不重新训练检索器或智能体的情况下，能够以低成本调整执行/跳过边界。在对 288 个收集的 rollout 进行的查询级留出评估中，RADEG 大幅减少了不必要的智能体执行，同时保留了大部分下游验证器奖励。在不同执行预算下，它始终优于基于相关性和随机门控的方法，表明执行感知的替代建模为技能检索提供了实用且经济高效的补充。

## Abstract
Agent skills are increasingly used to equip large language model (LLM) agents with reusable procedural knowledge. Although recent work has substantially improved skill retrieval due to the increasing skill libraries, retrieving a plausible skill bundle does not guarantee that executing it is worthwhile. Since every skill-conditioned rollout is computationally expensive, deciding whether a retrieved bundle should be executed has become an increasingly important challenge. To this end, we introduce the Reward-Aware Dynamic Execution Gate (RADEG), a lightweight, retriever-agnostic decision layer between skill retrieval and agent execution. RADEG learns a low-cost surrogate model that predicts the execution utility of a query--bundle pair before the expensive rollout is launched. To obtain informative supervision while controlling for task difficulty, we locally perturb each retrieved bundle by deleting, adding, or replacing one skill, producing matched same-query rollouts that isolate the effect of bundle composition on verifier reward. During deployment, RADEG updates only a warm-started logistic head as new verifier feedback becomes available, enabling inexpensive adaptation of the execute/skip boundary without retraining either the retriever or the agent. Under a query-level held-out evaluation on 288 collected rollouts, RADEG substantially reduces unnecessary agent executions while preserving a large fraction of the downstream verifier reward. It consistently outperforms relevance-based and random gating across different execution budgets, demonstrating that execution-aware surrogate modeling provides a practical and cost-effective complement to skill retrieval.

## 1. 论文的核心问题与整体含义（研究动机和背景）

- **背景**：基于技能的 LLM 智能体通过技能库（skill library）封装可复用的程序性知识。随着技能库规模增大，主流方法将“技能选择”视为检索/路由问题，强调查询-技能之间的相关性（如 PPR、稠密检索、重排序等）。
- **核心问题**：检索到“相关”的技能组合（skill bundle）并不等于执行它是“值得”的。技能条件化的执行过程（rollout）会消耗大量 API 调用、token、工具交互和墙钟时间，即使最终验证器奖励为零。论文称这一现象为 **相关性-效用鸿沟（relevance–utility gap）**。
- **研究意义**：在技能检索与智能体执行之间增加一个独立的、轻量级的“执行门控”决策层，用低成本代理模型预测“执行该查询-技能包是否可能产生正验证器奖励”，从而避免大量不必要的高成本执行。该问题是成本效率优化的重要方向，且检索器与智能体均可保持不变，便于集成到现有流水线。

## 2. 论文提出的方法论：核心思想、关键技术细节、公式与算法流程

### 2.1 核心思想

- 提出 **RADEG（Reward-Aware Dynamic Execution Gate）**：一个位于检索器（R）与智能体（A）之间的后检索、预执行决策层。
- 它学习一个替代模型，对查询-技能包对 `(q, b)` 预测“正验证器奖励”的概率，即 `s_θ(q, b) ≈ Pr(r(q, b) > 0 | q, b)`，然后根据阈值 τ 决定执行（g=1）或跳过（g=0）。
- 关键点：利用历史 `(query, bundle, reward)` 记录进行离线训练，并在部署时仅更新一个轻量逻辑回归头，无需重新训练检索器或智能体。

### 2.2 查询-技能包编码

- 使用固定文本编码器 `E`（文中为 `all-MiniLM-L6-v2`，384维）分别编码查询 `q` 和每个技能 `s` 的规范描述（如 SKILL.md）。
- 技能包表示采用平均池化：`e_b = (1/|b|) Σ_s E(d_s)`。
- 核心联合表示：`x_sem(q, b) = [e_q ∥ e_b]`（拼接）。
- 另附加实现相关的辅助特征：四维 bundle-condition 指示向量、四个 GoS PPR 统计量，构成完整输入 `x(q, b)`。

### 2.3 离线效用学习

- 输入表示经 MLP（776 → 256 → 128 → 64，ReLU + dropout 0.3）得到效用编码 `h_φ(x)`。
- 逻辑输出头：`s_i = σ(w^T h_i + c)`，待估 `Pr(r_i > 0 | q_i, b_i)`。
- 训练损失：类别加权二元交叉熵 `L_off = -(1/N) Σ [ω_+ y_i log s_i + (1-y_i) log(1-s_i)]`，其中 `ω_+ = N_neg / N_pos` 处理正负样本不平衡。
- 这一步得到冻结的效用编码器 `h_φ` 和初始执行头 `(w, c)`。

### 2.4 奖励感知动态门控（在线更新）

- 冻结编码器，只更新逻辑回归头。
- 每次获得验证器反馈 `r_t` 后，构造标签 `y_t = I[r_t > 0]`，执行一步在线梯度下降：`(w_{t+1}, c_{t+1}) = (w_t, c_t) - η ∇ ℓ(σ(w_t^T h_t + c_t), y_t)`。
- 决策规则：`g_t = I[s_t ≥ τ]`，τ 控制执行频率与保留奖励之间的权衡。

### 2.5 数据集构造方法

- 为获得监督信号并控制任务难度，对已检索的技能包进行**局部扰动**：
  - **Delete Top**：删除 PPR 最高技能；
  - **Add Irrelevant**：添加一个低相似度技能；
  - **Replace Similar**：用一个图结构相似技能替换原技能。
- 同一查询的多种变体产生匹配的相同查询 rollout，从而隔离“技能包组成”对奖励的影响。

## 3. 实验设计：数据集、场景、基准与对比方法

### 3.1 数据集与场景

- **主基准**：SkillsBench（72 个任务）。
- **数据规模**：72 个查询 × 4 种技能包条件 = **288 个 rollout**，其中正奖励 94 个，零奖励 194 个；部分奖励（0<r<1）占正例的 25.5%。
- **执行环境**：Docker + Claude-Code 风格，模型标识为 Claude Sonnet 4.6（通过第三方 API 中继），验证器为 SkillsBench 确定性任务验证器（奖励 ∈ [0,1]）。

### 3.2 评估协议

- **查询级留出**：所有围绕同一查询的 4 个 bundle 变体放入同一分区，避免数据泄漏。
- 主要对比使用 **5 个共享的查询级随机划分**；另做 **30 个划分**分析不确定性。
- 离线训练约占 70% 查询，其余作为未见评估流。
- **固定预算评估**：`RR@β` = 在只允许执行 β 比例调用时的保留奖励（β = 20%, 40%, 60%, 80%）；随机排序平均 2000 次，差异用 3000 次 query-level bootstrap 评估。

### 3.3 对比方法

- **Always-Execute**：执行所有调用（归一化参考），奖励/调用 = 0.309。
- **Random-Gate**：随机排序。
- **PPR-Gate**：用 GoS 聚合 PPR 相关性作为执行分数。
- **Static Head**：离线训练后冻结，不做在线更新。
- **Memory-Corrected Head**：静态预测 + 最近邻记忆中的正例频率混合。
- **Oracle**：后验上界（不可部署）。
- 另对比 **GCN Gate**（利用技能依赖图的图卷积编码器）。

### 3.4 扩展实验

- **跨智能体适应**：从 Sonnet 训练的 checkpoint 转移到 Qwen3.7-Max、DeepSeek-Chat、GLM-5.2 等目标智能体，分静态、per-target adaptation、continual adaptation 三种协议。
- **跨检索器与包大小**：使用 Hybrid、BM25、Embedding 三种检索策略，以及 Top-8 vs Top-7 变体。
- **选择性反馈与探索**：ε-greedy 探索不同取值（0, 0.05, 0.1, 0.2, 0.5, 1.0）。
- **特征消融**：分别去除查询嵌入、包嵌入、bundle-condition 特征、PPR 统计量。
- **跨基准泛化**：τ-Bench、AgentDojo、ToolSandbox 三个工具智能体基准（每基准 60 次执行，共 180 条额外数据），构造 Gold / Halfmix / Distractor 工具包条件。

### 3.5 主要结果

- 主表（5-split）：RADEG AUROC=0.717，AUPRC=0.570；τ=0.5 时跳过 68% 调用、保留 61% 奖励，奖励/调用从 0.309 提升到 0.483（+56%）。
- 固定预算：20% 预算下 RADEG 保留 40% 奖励，显著优于 PPR-Gate（15%）和 Random-Gate（19%）；所有预算下 RADEG 均获胜，bootstrap p<0.001。
- 30-split：AUROC=0.747±0.059，AUPRC=0.595±0.095，表明主结果具有稳定性。
- 跨智能体：Qwen3.7-Max AUROC 0.733、DeepSeek-Chat 0.628、GLM-5.2 0.752（per-target 预流式评估），说明迁移可行但依赖目标。
- 跨检索器：混合检索 Top-8 AUROC=0.750，BM25/嵌入检索=0.683；Distractor 构造最低（0.542），表明对自然检索分布泛化较好。
- 特征消融：去除 bundle embedding 时 AUROC 降幅最大（0.744→0.730），但差异均在 split 变异性范围内，不宣称统计显著。

## 6. 论文的主要结论与发现

- **相关性不等同于效用**：GoS 检索的 PPR 相关性与验证器奖励之间几乎没有关联（Spearman 接近 0，AUROC<0.5），扰动实验显示 22/72 个任务在局部扰动下奖励发生变化，并出现 17 次 0→正 和 15 次 正→0 的翻转。
- **RADEG 能有效预测执行效用**：在查询级留出评估中显著优于 PPR-Gate、随机门控、静态头与记忆修正头，AUROC 从 0.608 提升到 0.717（相对于最优基线），同时保留大部分奖励并大幅降低执行次数。
- **在线头更新带来收益**：仅更新逻辑回归头即可适应新反馈，无需重训练模型，证明轻量动态门控可行。
- **固定预算下优先性能更强**：在低执行预算（20%）下 RADEG 的保留奖励约是 PPR-Gate 的 2.7 倍、随机门控的 2.1 倍，说明效用预测对成本敏感场景价值最大。
- **对检索器和智能体具有通用性**：在不同检索策略、不同包大小、不同下游智能体以及 τ-Bench、AgentDojo、ToolSandbox 等独立基准上均表现出正迁移能力。
- **执行感知建模是技能检索的实用补充**：门控层可以不改动现有检索器和智能体，独立部署并带来显著成本效益。

## 7. 优点

- **问题定义清晰**：明确区分“检索相关性”与“执行效用”，指出当前检索评估指标（Hit@K、MRR、NDCG）的盲区。
- **方法轻量且通用**：RADEG 与检索器无关、与智能体无关，只需轻量 MLP 和逻辑头，CPU 上运行，在线更新成本极低。
- **数据构造巧妙**：通过局部扰动技能包生成“匹配对”来隔离技能组成对结果的影响，控制任务难度，为弱监督数据的可解释性提供了良好范例。
- **评估协议严谨**：采用查询级划分防止泄漏、固定预算对比、bootstrap 显著性检验、30-split 不确定性分析，方法对比在同协议下进行，结论可信度高。
- **探索了多种实际场景**：跨智能体、跨检索器、选择性反馈、外部工具基准，展示系统在不同部署条件下的适应性。
- **量化了开销**：专门测量门控延迟与端到端智能体运行时间，证明门控开销可忽略，实用性有说服力。

## 8. 不足与局限

- **数据规模小**：仅 288 条主数据集 rollout，外部基准 180 条，正例稀少（主集正例 94 条），限制了模型的泛化能力和统计功效。
- **扰动类型有限**：仅考察删除最高 PPR、添加不相关、替换相似三种局部扰动，未覆盖更大范围的结构性变化（如多技能增删、技能顺序变化、依赖关系重组）。
- **选择性反馈 bias**：部署时被跳过的调用没有标签，只能通过 ε-greedy 探索部分弥补；论文承认缺失标签是性能下降的重要原因，且探索会增加执行成本，实际部署中的最优探索策略未给出。
- **跨智能体适应性有局限**：目标智能体的 AUROC 差异较大（DeepSeek-Chat 仅 0.628），且部分目标只有一两个正例（标记为 underpowered），无法可靠评估迁移效果；源执行链（Claude-Code 风格）与目标智能体 scaffold 可能不同，混淆模型层级差异。
- **特征工程依赖上游**：输入包含 GoS 特定的 PPR 统计量和 bundle-condition 向量，若上游检索器不提供此类元数据，特征需要调整或置零（论文在外部基准中将图相关特征置零，但未深入讨论对性能的影响）。
- **缺乏端到端成本测量**：论文只报告了保留奖励等归一化指标，没有给出实际节省的 API 费用、token 数量和墙钟时间的量化数字，仅提供了门控延迟与执行时长对比。
- **统计显著性受限**：特征消融和部分跨智能体/探索率差异在拆分间不显著，无法区分真正的贡献与噪声；部分实验（如 GCN）单一实现测试不足，不能否定图结构建模的潜在价值。
- **验证器依赖**：门控依赖任务特定验证器的奖励反馈，若验证器本身有偏或奖励不可靠，门控的学习信号会受到污染。
