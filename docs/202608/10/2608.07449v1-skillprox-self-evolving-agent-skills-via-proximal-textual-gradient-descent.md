## 摘要
大语言模型智能体通过将程序性知识积累到技能中，日益适应重复性任务。这些技能是轻量级、可复用的文本工件，在无需权重更新的情况下加载到智能体的上下文中。近期方法通过迭代任务执行、故障诊断和轨迹引导的文本空间更新来细化技能。然而，现有框架缺乏显式的诊断——结果反馈，并将删除视为一种通用编辑操作，而非一种用于整合累积知识的专门机制。我们提出SkillProx，一种受近端梯度启发的正向-反向框架，将闭环诊断式进化与效用感知的近端细化相结合。受平衡任务损失与技能复杂性的复合目标驱动，前向阶段在同一任务批次上重新执行诊断驱动的编辑，回滚回归，并将测量结果反馈到后续诊断中。反向阶段将所得技能分解为可审计的知识单元，使用冻结的留一法效用审计估计其贡献，并应用验证门控的整合、降级或移除。在多个骨干大语言模型上的分布内和分布外基准实验中，SkillProx相较于最强的基于梯度的基线，平均准确率提升了3.0个百分点。组件消融实验证明了闭环诊断与近端细化的互补效应。

## Abstract
LLM agents increasingly adapt to recurring tasks by accumulating procedural knowledge in skills. These skills are lightweight, reusable textual artifacts that are loaded into the agent's context without weight updates. Recent methods refine skills through iterative task execution, failure diagnosis, and trajectory-guided text-space updates. However, existing frameworks lack explicit diagnosis--outcome feedback and treat deletion as a generic edit operation rather than a dedicated mechanism for consolidating accumulated knowledge. We introduce SkillProx, a proximal-gradient-inspired forward--backward framework that couples closed-loop diagnostic evolution with utility-aware proximal refinement. Motivated by a composite objective balancing task loss and skill complexity, the forward stage re-executes diagnosis-driven edits on the same task batch, rolls back regressions, and feeds measured outcomes into subsequent diagnoses. The backward stage decomposes the resulting skill into auditable knowledge units, estimates their contributions using a frozen leave-one-out utility audit, and applies validation-gated consolidation, demotion, or removal. Experiments on in-distribution and out-of-distribution benchmarks across multiple backbone LLMs show that SkillProx improves average accuracy by 3.0 percentage points over the strongest gradient-based baseline. Component ablations demonstrate the complementary effects of closed-loop diagnosis and proximal refinement.

**研究动机与背景：**

- 大语言模型（LLM）智能体日益通过将程序性知识外部化为 **技能（Skill）** 来适应重复性任务。技能是轻量级、可复用的文本工件（如 `SKILL.md` 加引用文件），在推理时加载进上下文而非更新模型权重。
- 现有技能生成方法（如 Trace2Skill、EvoSkill）偏重**一次性合成**，但 SkillsBench 等基准表明：一次性构建的技能难以应对后续多样性任务，甚至可能带来负面收益，因此需要**技能演化**——即从静态构建走向动态迭代更新。
- 已有技能演化方法（如 SkillGrad、SkillOpt）存在两大严重缺陷：
  1. **前向更新未经验证**：LLM 生成的诊断被认为天然是有效的更新方向，补丁生成后直接提交，既不重执行验证效果，也不把结果反馈给后续诊断；
  2. **技能无节制膨胀**：迭代打补丁不断扩充技能，但没有机制重新评估已积累的知识，导致重复指令、冲突启发式、过度泛化的任务特化内容不断堆积，干扰有用知识。
- 核心研究问题：**如何将"结果验证的前向诊断"与"结构感知的后向精修"耦合，使技能的任务能力和结构复杂度共同演化？**

**核心贡献：**

- 将技能演化形式化为一个复合优化问题（任务损失 + 技能复杂度），识别出现有方法缺失的两个组件：前向更新的结果验证与累积知识的效用引导正则化；
- 提出 **SkillProx** 框架：前向闭环诊断演化（同批次重执行、回滚、重试、接受/拒绝记忆）+ 后向验证门控近端收缩（效用审计驱动合并、降级、删除）；

## 2. 方法论

**整体框架（正向-反向二分，类比近端梯度下降）：**

SkillProx 借鉴近端梯度下降（PGD）的思想：前向步负责优化任务目标，后向近端步负责控制结构复杂度。将技能文本视为不可微的离散对象，前向用"诊断演化"作为不精确的任务性能算子，后向用"效用感知整合"作为离散的复杂度控制算子。整个流程为：

```
初始技能 X0 → 前向闭环诊断演化 → 中间技能 Xf → 后向近端收缩 → 最终技能 X*
```

**前向阶段——闭环诊断演化（Closed-Loop Forward Update）：**

- 在第 k 次迭代，当前技能 Xk 在训练批次 Bk 上执行；诊断器（Diagnostician）基于失败轨迹、对比成功轨迹、最近接受/拒绝历史和上一次尝试的拒绝原因，提出编辑方向；
- 补丁器（Patcher）从迭代前快照生成候选技能 X~k^(j)，然后在**同一任务批次**上重新执行该候选；
- 接受门控（Gate）要求硬准确率和平均单元格准确率均不低于更新前：
  - 若候选带来的硬准确率严格提升，提前终止搜索；否则最多尝试 3 次，选出按（硬、单元格）字典序最优的候选，仍需满足门控条件；
  - 被拒绝的更新回滚到迭代前状态，其观测到的准确率变化和尝试方向作为反馈注入后续诊断；
- 跨迭代保存最 6 次接受/拒绝记录，形成语义历史供后续诊断参考；
- 门控仅约束当前批次，不保证验证集/测试集上的单调性。

**后向阶段——冻结效用审计与近端收缩（Prox）：**

- **知识单元分解**：将前向得到的技能 Xf 解析为可审计的 L2 章节和 L3 引用组 Q(Xf) = {q₁,...,qₙ}；
- **冻结留一法效用审计**：对每个单元 qᵢ，构造完全删除该单元的副本 Ablate(Xf, qᵢ)，在固定验证集 V 上计算边际效用：
  - u_hard^i = HV(Xf) − HV(Ablate(Xf, qi))
  - u_cell^i = CV(Xf) − CV(Ablate(Xf, qi))
  - 正值表示该单元有正向贡献；负值表示删除后效果更好。所有效用只测一次并冻结。
- **候选筛选与排序**：选择单元格效用低于阈值 τ = −0.001 的单元作为候选，按（单元格效用，硬效用）字典序升序处理；
- **单遍验证门控收缩**（Shrinker）：
  - 对每个候选，生成一次合并、降级或删除的试验编辑 Tm，要求满足结构有效性且严格降低文本复杂度 G；
  - 在验证集上评估，要求硬准确率不降（δh = 0），平均单元格准确率最多降 0.02（δc = 0.02），累积压缩比达到 10%（ρ = 0.10）之前继续尝试（软上限）；
  - 通过全部门控则替代当前活跃技能，否则丢弃该试验；每个候选至多处理一次；
  - 被先前合并已移除目标的候选跳过。

**与标准 PGD 的对应关系（论文表 1）：** 前向方向对应自然语言诊断方向而非解析梯度；前向更新对应诊断-打补丁-同批次重执行-拒绝反馈-回滚；后向步对应冻结效用审计 + 语义收缩 + 结构检查 + 验证门控；局部性通过单目标编辑和软压缩上限实现。

## 6. 论文的主要结论与发现

1. **SkillProx 在所有骨干上均将人工基准技能转化为净正信号**（如 Qwen3.5-27B 上 38.3→51.3，提升 13 pp；Qwen3.6-27B 上 36.7→54.5，提升 17.8 pp），在 IID 和 OOD 上都带来稳定增益；
2. **在 IID 任务（SpreadsheetBench）上全面优于 LLM 生成技能和自演化技能基线**，且方差最低（如 Qwen3.6-27B 上 ±0.5，SkillOpt 为 ±7.6）；
3. **OOD 泛化能力强**：SkillOpt 过拟合 IID 风格并在 OOD 上崩溃（如 4B 上 WikiTQ 仅 26.0），而 SkillProx 在多数 OOD 场景取得最佳或次佳；
4. **两个组件互补**：移除闭环诊断降 1.5 pp，移除 Prox 降 2.5 pp——前向闭环提供在线拦截，后向 Prox 提供事后的知识整合；
5. **适度的技能压缩可以同时提高压缩率和准确率**：τ = −0.001 时达到最高精度（52.3%），压缩 25.7%；τ = 0.050 时删除 74.9% 内容仍保持 51.0% 准确率；压缩超过约 80% 后性能才开始下降；
6. **模型规模影响技能表征方式**：4B 模型需要更长的参考文件（约为 27B 的两倍），其更新更频繁地被门控拒绝；27B 模型天然更善于生成精简技能；
7. **门控机制倾向于筛选"可证伪的编辑"**：同一故障模式，开环学到的是难以验证的元指令（"trace carefully"），闭环学到的是可执行的决策规则（"更新参考值"），效用从 −0.0337 翻转为 +0.0495。

3. **机制设计完整**：前向有同批次重执行、回滚、重试、接受/拒绝记忆，后向有冻结效用审计 + 验证门控 + 结构校验 + 软压缩上限，各环节都有明确目标和终止条件；
4. **有限样本下的细节刻画**：从 22 次尝试的门控追踪、逐任务 fail-to-pass 列表到候选级验证决策，提供了丰富的过程级证据，而非仅报告最终分数；
5. **对自身局限坦诚**：明确承认验证集小、案例分析的观察性质、相关系数的敏感性，不夸大因果结论；
6. **工程考虑周到**：LibreOffice 重算、操作串行化、隔离目录、vLLM 端点的故障切换等实现细节体现了实验的严谨性。

## 8. 不足与局限

1. **核心概念近似性**：论文明确承认 Jλ(X) 复合目标、λ 和 η 都不是方法实际优化的量，PGD 类比是"概念性"而非"算法性"的。这使得理论贡献（如收敛性分析）较薄弱——附录只有"有限终止 + 记录性下界"，没有真正的收敛证明；
2. **验证集规模过小**：效用审计仅用 20 个验证任务 + 每个测试 1 个用例，噪声大，论文也称效用分数是"候选证据"而非确定性评估。这限制了 Prox 选择的可靠性；
3. **OOD 评估领域单一**：三个基准全部落在"表格数据处理"范围内（SpreadsheetBench、WikiTQ、HiTab），未覆盖代码生成、多轮对话、工具调用等更广泛的智能体任务，泛化结论的外部效度有限；
4. **统计功效有限**：主要结果基于 3 个种子，种子间方差较小是优点，但 3 个种子的均值估计置信区间仍然较宽；部分案例分析仅基于单一种子（种子 8），论文也承认不应外推为平均效应；
5. **计算成本高**：留一法效用审计需要进行 n 次完整评估（将全部验证集任务跑一遍），前向还包含同批次重执行和最多 3 次尝试，整体推理调用量显著高于开环方法，论文未提供端到端成本对比；
6. **潜在的选择偏差**：种子 8 被选中做案例研究恰因其是开环最差表现者，差距最大；论文承认这是观察性对比而非受控 A/B 实验，但读者在引用"5 点提升"时仍需谨慎；

## 9. 总结与展望

SkillProx 在技能演化这一新兴课题上做出了有价值的探索，其核心思想——**将“前向诊断的闭环验证”与“后向知识的效用收缩”解耦并耦合**——不仅解决了现有方法“只增不删、盲目打补丁”的痛点，也为后续研究提供了清晰的可扩展框架。尽管存在验证集规模小、OOD 领域单一、理论分析偏概念化、计算成本较高等局限，但其在多个骨干模型与基准上的稳定增益、细致的机制分析和坦诚的自我审视，使之成为该方向上一个扎实的里程碑。未来工作可沿以下方向推进：扩大验证集与任务类型（代码、对话、工具调用）、引入自适应阈值或贝叶斯超参数优化、降低效用审计的推理开销（如近似留一法）、以及从梯度流角度给出更严格的收敛性分析。总体而言，SkillProx 证明了“技能也需要持续校准与修剪”这一理念的可行性，对 LLM 智能体的长期自演化研究具有重要参考意义。
