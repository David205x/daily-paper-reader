## 摘要
大型语言模型（LLMs）通常因其对静态内部知识的依赖而生成不准确的答案。检索增强生成（RAG）通过整合外部知识解决了这一局限性，并在单跳查询中表现出色。然而，它在需要跨文档推理的多跳问题上表现不佳。现有方法，如图结构RAG或问题分解，往往缺乏动态分解和有效过滤，导致效率和准确性较低。为克服这些局限性，我们提出了面向多跳推理增强生成的动态分解与过滤（D2F-ReAG），一种新颖的范式，通过判断根级推理的可靠性来自适应控制推理深度。如果根级推理可靠，模型直接生成答案。否则，将问题逻辑分解为子问题，并利用从这些子问题中得出的已验证推理来完善根级推理。在三个多跳基准上的实验证明了我们方法在处理复杂多跳问题方面的有效性。

## Abstract
Large language models (LLMs) often generate inaccurate answers due to their reliance on static internal knowledge. Retrieval-augmented generation (RAG) addresses this limitation by integrating external knowledge and excelling at single-hop queries. However, it struggles with multi-hop questions that require cross-document reasoning. Existing methods, such as graph structured RAG or question decomposition, often lack dynamic decomposition and effective filtering, which leads to lower efficiency and accuracy. To overcome these limitations, we propose Dynamic Decomposition and Filtering for Multi-Hop Reasoning-Augmented Generation (D2F-ReAG), a novel paradigm that adaptively controls reasoning depth by judging the reliability of the root-level reasoning. If the root reasoning is reliable, the model directly generates the answer. Otherwise, the question is logically decomposed into sub-questions, and the verified reasoning derived from these sub-questions is used to refine the root reasoning. Experiments on three multi-hop benchmarks demonstrate the effectiveness of our method in handling complex multi-hop questions.

- 现有解决方案存在两类典型缺陷：
  - **图结构 RAG**（如 GraphRAG、HippoRAG 等）：依赖预构建知识图谱，构建和维护成本高，难以应对知识更新，且图结构不完整时检索效果受限。
  - **基于提示词的问题分解方法**（如 LogicRAG、ChainRAG 等）：分解策略固定、缺乏自适应性，简单问题易被过度分解，复杂问题分解深度不足；同时缺乏有效的中间结果过滤，冗余或错误信息会在推理迭代中累积，误导最终答案。
- 论文提出 **D²F-ReAG（Dynamic Decomposition and Filtering for Multi-Hop Reasoning-Augmented Generation）**，旨在通过“按需分解 + 可靠性过滤”实现自适应深度控制，在提高多跳问答准确性的同时避免不必要的计算开销。

## 2. 提出的方法论：核心思想与关键细节

### 核心思想
- 利用 LLM 作为“裁判”，对当前根级推理的可靠性进行打分。
- 可靠 → 直接生成最终答案；不可靠 → 将问题逻辑分解为子问题，依次求解，并将**已验证且与根问题相关**的子问题推理动态回传，逐步修正和完善根级推理。
- 整个过程支持**早期停止**，防止过度推理和噪声引入。

### 关键技术细节与流程
1. **检索与生成（Retrieval & Generation）**
   - 对根问题或每个子问题，用稠密检索器从语料库中召回 top-k 文档，再让生成模型基于检索文档产生推理过程：
     \[
     r(q) = \text{Generator}(q, D(q))
     \]
   - 显式条件化检索证据，鼓励模型进行基于证据的推理而非单纯依赖参数记忆。

2. **可靠性判断（Judge Reliability）**
   - 使用 LLM 按预定义评分规则对推理过程打分：
     \[
     s_r(q) = \text{Score}(q, r(q))
     \]
   - 评分维度包括证据一致性、逻辑连贯性和答案完整性，分数范围 [0, 10]。
   - 若 \( s_r(q) > \theta \)（实验取 \(\theta=7\)），判为已解决；否则触发分解。

3. **分解与重写（Decomposition & Rewriting）**
   - 对未解决的根问题或子问题，通过提示工程进行逻辑分解：
     \[
     \text{sub}(q) = \text{Decompose}(q)
     \]
   - 先依次求解子问题，并根据已求得的可靠推理对其他相关子问题执行重写：
     \[
     S'_i = \{ \text{Rewrite}(q, r_q) \mid q \in S_i \}
     \]
   - 重写可消解模糊指代、补全缺失实体，提高后续检索质量。

4. **推理增强（ReAG，Reasoning-Augmented Generation）**
   - 对已可靠求解的子问题，先检查其与根问题的相关性（避免无关信息污染全局状态），再将其推理整合进根推理：
     \[
     r'(q_{\text{root}}) = \text{Update}(r(q_{\text{root}}), r(q))
     \]
   - 一旦根推理可靠性超过阈值，立即停止处理剩余子问题，输出最终答案。

### 总体流程总结
- 根问题检索 → 生成推理 → 可靠性判断 →（可靠则直接回答；不可靠则分解/重写 → 子问题求解 → 验证与过滤 → 更新根推理 → 再判断）→ 循环直至可靠或达到停止条件。

## 3. 实验设计：数据集、基准与对比方法

### 数据集与评测基准
- 使用三个标准多跳推理 benchmark：
  - **HotpotQA**（多跳、可解释问答）
  - **2WikiMultiHopQA**（基于维基百科的多跳推理，含比较、桥接等类型）
  - **MuSiQue**（更困难的多跳组合问答）
- 评测设置：参照 HippoRAG 2，统一使用相同检索语料库，从每个验证集中随机采样 1000 个问题。
- 指标：
  - **Str-Acc**：严格词面匹配准确率（标准化后是否与标准答案完全一致）。
  - **LLM-Acc**：用强 LLM 判断预测与参考答案是否语义等价（容忍改写和同义表达）。

### 对比方法（Baselines）
- **Zero-shot 直接提示**：Llama3 8B、Llama3 13B、GPT-3.5-Turbo、GPT-4o-Mini。
- **图结构 RAG**：RAPTOR、GraphRAG、LightRAG、HippoRAG、HippoRAG 2。
- **基于提示词的 RAG**：VanillaRAG、ReAct、ChainRAG、LogicRAG（其中部分为作者复现，标注 †）。

### 实现细节
- 检索器：`sentence-transformers/all-MiniLM-L6-v2`
- top-k = 3
- 生成与判断骨架：`gpt-4o-mini`
- 所有方法使用相同的检索器和 backbone，保证公平比较。

## 6. 主要结论与发现

- D²F-ReAG 在三个多跳基准上均优于所有基线，尤其在 2WikiMultiHopQA 上提升显著（Str-Acc 70.3，LLM-Acc 68.9），较最强提示方法 LogicRAG 分别提高 5.4 和 6.3 个百分点。
- 动态分解能有效平衡简单与复杂问题：大量简单问题无需分解即可直接正确回答，避免了固定分解带来的过度推理和噪声累积。
- 可靠性过滤和子问题推理回传机制能捕获中间错误并及时修正，降低跨步骤错误传播，使最终答案在词面和语义两个维度都更准确。
- 早期停止策略在保证准确性的同时降低计算开销，相比“始终分解”显著减少了时间和 token 消耗（平均时间 32.4s vs 73.5s；平均 token 6057 vs 13321）。
- 整体上，按需、适应性、经过验证的推理增强生成范式比固定深度分解或图结构方法更契合复杂多步问答的需求。

## 7. 优点与亮点

- **方法新颖性**：将“可靠性驱动的动态分解”与“子问题推理回传”结合，形成闭环：分解 ⇄ 验证 ⇄ 更新 ⇄ 再判断，实现了真正的按需推理。
- **可解释与可信赖**：每一步推理都经过显式评分，只用通过验证的子问题结果更新根推理，可追溯性强，降低黑箱风险。
- **兼顾效率与准确率**：通过阈值和早期停止，避免对简单问题过度计算，同时在困难问题上进行足够深的探索。
- **重写机制设计巧妙**：利用已验证信息重写后续子问题，解决指代模糊和实体缺失问题，提升检索命中率。
- **实验对比全面**：涵盖 zero-shot、图 RAG、提示 RAG 三大类主流方法，并做了效率分析和案例研究。
- **基准统一**：统一检索器、模型、语料和采样规模，突出了所提框架带来的收益，而非模型规模差异。

## 8. 不足与局限

- **评测规模有限**：仅使用每个验证集 1000 条子集，未报告全量验证或测试集上的结果，统计置信度有限。
- **依赖大模型作为裁判**：可靠性打分和最终判断都由 LLM 承担，存在打分偏差或不一致的风险；阈值 \(\theta=7\) 是经验固定值，缺少敏感性实验。
- **仅采用单一检索器和单一生成 backbone**：未验证在不同规模 LLM（如更小的开源模型）或不同嵌入模型下的鲁棒性。
