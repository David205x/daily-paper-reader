## 摘要
机器学习工程（MLE）任务需要在迭代的解决方案调试与优化过程中进行长周期决策，同时面临昂贵且反馈驱动的环境交互。为这类任务开发和训练一个单体智能体从根本上具有挑战性，因为它必须同时管理极长且嘈杂的上下文、探索庞大的解决方案空间，并在有限的模型容量和计算预算下保持有效性。为解决这些挑战，我们提出了套娃智能体（Matryoshka Agent），一个面向复杂长周期任务的统一分层智能体框架。套娃智能体将智能体问题求解分解为决策与执行的协调层级：高层编排器（Orchestrator）维护紧凑的长周期探索状态并发出策略性指令，而低层子智能体（Sub-Agents）通过直接环境交互执行具体的解决方案尝试，并通过标准化的工具接口进行中介。这一设计将策略性探索与昂贵的执行解耦，大幅减轻了长上下文推理的负担，并实现了高效的迭代优化。我们进一步为套娃智能体开发了一种高效的训练范式。在涵盖多种模型类型和规模的广泛MLE任务上的实验结果表明，套娃智能体是长周期MLE任务和复杂智能体问题求解的有效且可扩展的范式。值得注意的是，套娃智能体使Qwen3-4B-Instruct达到了与o4-mini相当的编排器性能。将套娃智能体应用于Qwen3-30B-Coder，相对性能提升最高可达36.7%。

## Abstract
Machine learning engineering (MLE) tasks require long-horizon decision making over iterative solution debugging and refinement, under expensive and feedback-driven environment interactions. Developing and training a monolithic agent for such tasks is fundamentally challenging, as it must simultaneously manage extremely long and noisy contexts, explore vast solution spaces, and remain effective under limited model capacity and computational budgets. To address these challenges, we propose Matryoshka Agent, a unified hierarchical agent framework for complex long-horizon tasks. Matryoshka Agent decomposes agentic problem solving into a coordinated hierarchy of decision making and execution: a high-level Orchestrator maintains compact, long-horizon exploration states and issues strategic instructions, while lower-level Sub-Agents execute concrete solution attempts through direct environment interaction, mediated by standardized Tool interface. This design decouples strategic exploration from costly execution, substantially reducing the burden of long-context reasoning and enabling efficient iterative refinement. We further develop an efficient training paradigm for Matryoshka Agent. Experimental results on a broad range of MLE tasks with diverse model types and scales demonstrate that Matryoshka Agent is an effective and scalable paradigm for long-horizon MLE tasks and complex agentic problem solving. Notably, Matryoshka Agent enables Qwen3-4B-Instruct to reach Orchestrator performance comparable to o4-mini. Applying Matryoshka Agent to Qwen3-30B-Coder results in at most 36.7% relative performance gain.

- **单体智能体的根本困境**：MLE 任务天然产生极长且充满噪声的上下文（执行日志、调试反馈持续累积）；解决方案空间开放且巨大；环境交互昂贵（耗时和算力）。单体智能体必须同时管理这些压力，在有限模型容量与计算预算下极易出现上下文饱和、局部最优和效率下降。
- **本文提出的解答**：引入分层架构 **Matryoshka Agent（套娃智能体）**，将"战略决策"与"具体执行"解耦，从而降低长上下文推理负担、提升可扩展性，并配合一种高效的在线迭代训练范式，在复杂 MLE 任务上取得了明显提升。

## 2. 方法论

### 2.1 分层框架（推理期）

- **Orchestrator（编排器）**：高层决策层。维护跨轮次的紧凑状态（指令记录、结果摘要、评分），不累积原始日志；每轮决定三件事：①选择哪个先前尝试作为基准进行优化；②发出具体的实现指令（模型选择、预处理、超参数、集成方案等）；③标签哪些先前尝试作为参考注入给子智能体。
- **Sub-Agents（子智能体）**：执行层。每次以全新上下文启动，由工具接口组装上下文（任务说明+编排器指令+所选参考）；在本地完成"写代码→执行→调试→验证"的有界循环（默认最多 10 轮调试），产生有效提交或失败诊断，然后将摘要与分数回传。
- **Tools（工具接口）**：中介层。定义编排器与子智能体之间的信息边界；将高层指令翻译为可执行上下文，并将子智能体的执行轨迹浓缩为紧凑的工具响应；支持并行发起多个子智能体。

### 2.2 训练阶段：迭代在线优化

- **训练期解决方案精化树（Solution Refinement Tree）**：从根状态出发，当前编排器策略在每个非叶节点采样两条替代优化指令，分别由子智能体执行，形成二叉扩展树。节点为有评分的解决方案尝试，边为编排器的精化决策。
- **偏好构造**：对内部节点 u，其两个分支 c₁/c₂ 的**下游回报**为 R(c)=max_{v∈subtree(c)} r(v)。更高下游回报的分支视为偏好延续。分支级标签不惩罚"首轮得分低但后续提升快"的方向，同时保留长周期最优目标的监督信号。
- **在线强化学习（RL）**：采用基于能量模型的**排序式 NCE 目标**。最优策略具有能量形式 π\*(Δτ|s_u) ∝ π^(m)(Δτ|s_u)·exp(1/β·r(s_u,Δτ))；将分数参数化为对数比值 r_θ = β·log(π_θ/π^(m))，代入排序目标得到最终损失：
  - L_orch = −E_u[ β·log(π_θ(Δτ⁺|s_u)/π^(m)(Δτ⁺|s_u)) − log( Σ_{Δτ∈C(u)} (π_θ(Δτ|s_u)/π^(m)(Δτ|s_u))^β) ]
  - 该目标以 KL 式对数比值锚定上一轮策略，避免更新过激，并利用下游执行结果监督编排器决策。
- **子智能体自强化**：从精化树中提取最高分路径上的成功轨迹，构建（指令→响应）对，对子智能体做监督微调（SFT），以提升指令跟随与执行稳定性。

- **模型集合**：开源 Qwen3-4B-Instruct-2507、Qwen3-Coder-30B-A3B-Instruct；闭源 o4-mini、GPT-5-nano。同一模型可分别充当编排器和子智能体，亦支持跨模型组合（记作 Model A + Model B）。

  - Dojo Agent（原始单智能体）

  - Matryoshka Agent（无训练 / SFT / SFT+RL）

### 3.3 消融与辅助实验

- **编排器/子智能体贡献消融**：用 Qwen3-30B-Coder 与 Qwen3-30B-Coder-RL 交叉互换角色，检验两边收益大小。

- **上下文长度/指令长度分析**：对比编排器、子智能体、Dojo Agent 在不同轮次的累积 token 量；统计编排器在预训练/SFT/RL 阶段的平均指令长度。

## 4. 资源与算力

- 训练在 **NVIDIA H100 80GB HBM3 GPU**上进行（CPU 为 Intel Xeon Platinum 8580，Python 3.10.12）。
- **SFT**（8 卡规模配置）：Qwen3-4B 用 4 卡（张量并行 2、上下文并行 2）；Qwen3-30B-Coder 用 8 卡（张量并行 4、专家并行 8、上下文并行 2）；序列并行开启，max_length=32768，2 个 epoch。
- **在线 RL**：同样 8 卡集群，Qwen3-4B 用 4 卡（张量并行 2、流水线并行 2），Qwen3-30B-Coder 用 8 卡（流水线并行 4、专家并行 2），梯度累积 8 步，2 个 epoch；优化器 Adam，lr=1×10⁻⁵，cosine 衰减，warmup 0.1。

- **消融实验相对完整**：涵盖架构增益 vs SFT 增益、编排器 vs 子智能体贡献、无 SFT 的 RL、跨模型即插即用、上下文增长规律和指令动态分析，多角度归因性能来源。
- **公平性设计良好**：对比基线包含同协议 SFT 的受训单体（避免 SFT 效果混淆）；Dojo Agent 和 Matryoshka Agent 使用相同的上下文截断策略与 12 小时预算，并在附录补充了 per-task 均值（而非仅 best-of-three）以缓解方差质疑。

## 6. 主要结论与发现

1. **分层架构有效（无训练增益）**：Qwen3-30B-Coder 从单体的 0.3302 提升到同模型自配的 0.3652，纯架构改进即可带来收益。
2. **训练增益叠加**：SFT 后达 0.4197（优于受训单体 0.3857），叠加在线 RL 后达 0.4515，相对 Dojo 基线提升最高 **36.7%**，证明决策层优化与执行层自强化均有价值。
3. **小模型可追赶大模型**：Qwen3-4B 作单体仅 0.1878，但作为编排器（配 o4-mini 子智能体）在 SFT+RL 后达 0.5360，几乎追平 o4-mini 自配的 0.5465。
4. **决策层比执行层受益更大**：将 RL 版模型用作编排器（0.4258）比用作子智能体（0.3826）提升更明显，佐证长周期任务瓶颈在高层决策。
5. **SFT 是 RL 的重要热身**：仅 RL（无 SFT）也能提升（0.3901 vs 0.3652），但远不如 SFT+RL（0.4515）。
6. **即插即用泛化良好**：RL 训练过的编排器换接不同子智能体（GPT-5-nano）仍能显著提升性能。
7. **上下文效率可量化**：编排器上下文增速约 1202 token/轮，明显低于 Dojo Agent 的 1870 token/轮；在 256K 上下文预算下，Matryoshka Agent 可支持约 213 轮 vs 单体的 137 轮，子智能体上下文长度恒为常数。
8. **规模不对称**：小模型（Qwen3-4B）作为子智能体能力不足，即便编排器指令更详细仍难可靠执行（详细失败案例分析见附录 E）。

## 7. 优点

- **架构设计优雅**："编排器—工具—子智能体"的信息边界清晰，将长上下文推理负担与昂贵执行解耦，从结构上规避了单体智能体的上下文饱和问题。
- **训练范式有理论支撑**：将能量模型/log-ratio 参数化引入排序式 NCE 目标，结合树状采样，使昂贵的环境反馈得到多组共享前缀的对比信号，兼顾样本效率与策略稳定性。
- **实验设计注重归因**：通过受训单体基线、交叉角色消融、"仅 RL vs SFT+RL"、即插即用等设置，系统性地分离了架构、SFT、RL、模型规模的各自贡献。
- **强泛化证据**：即插即用实验说明训练所得编排器不依赖特定子智能体，具备在异构模型环境中的实用迁移价值。
- **上下文分析新颖且定量**：精确测量了编排器/子智能体/单体的上下文增长速率，将框架的可扩展性从定性描述提升为定量结论（213 vs 137 轮上限）。

## 8. 不足与局限

- **资源开销与外推性**：训练依赖大量真实执行环境交互（每任务 12 小时预算），成本高昂；12 小时上限可能低估长周期任务的真实难度，也可能对某些任务不必要地宽松。
- **不确定性与显著性缺失**：仅报告 best-of-three，缺乏置信区间和统计显著性检验；三平行试验在异构任务上的方差（中位数 std≈0.07）不可忽略。
- **SFT 数据依赖教师模型**：100 条高质量轨迹由 Gemini-2.5-flash 生成，存在教师偏差和领域覆盖有限的风险，未探究训练数据规模/质量对性能的敏感性。
- **小模型执行短板**：Qwen3-4B 无法胜任子智能体，框架的可推广性受制于子智能体规模；小模型的失败模式（指令粒度不足、语法幻觉）尚未彻底解决。
- **机制理解有限**：RL 内部的作用机制（如何精确定位高回报分支、如何避免局部最优，以及编排器决策的可解释性）未被深入分析。
- **方法边界**：框架聚焦 MLE 类评分型任务，其有效性在更一般的开放式长周期智能体任务（如网页导航、科研探索）中尚未验证。
- **输入限制**：所有 LLM 使用了官方默认 temperature（开源 0.7，闭源 1.0），未见对采样温度、并行子智能体数量、调试预算等超参的敏感性分析。
