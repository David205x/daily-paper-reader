## 摘要
强化学习是面向代码的大型语言模型的一种自然的后训练范式，因为生成的程序可以通过解析、执行、单元测试和结构分析来评估。然而，现有方法通常依赖稀疏的结果奖励或静态组合异质的密集信号，尽管语法有效性、可执行性、功能正确性和结构组织描述的是不同且逐级依赖的编程能力。我们提出了DHRCL，一种具有密集分层奖励和课程学习的强化学习框架。DHRCL将反馈分解为语法验证、执行成功、单元测试通过率和基于AST的结构相似性，并通过三阶段的语法、执行、通过及结构课程来组织这些信号。阶段持续时间根据最近的验证趋势自动确定，而非手动指定的能力阈值。我们进一步引入了阶段感知的概率性令牌信用重新分配机制。该机制遵循巩固到精炼的原则：在面向语法的优化过程中强调已建立的令牌模式，对非局部的执行反馈应用均匀传播，并在最终的功能优化过程中将更多信用或责任分配给尚未确立的令牌决策。在统一的Qwen3-8B和KodCode协议下，实验将DHRCL与二元、通过率、基于奖励模型和可验证的密集奖励基线进行了比较。我们还在Qwen3-4B、Qwen3-8B和Qwen3-14B骨干网络上评估了DHRCL，表明其优势随着模型容量的增加保持一致性。

## Abstract
Reinforcement learning is a natural post-training paradigm for code-oriented large language models because generated programs can be evaluated through parsing, execution, unit tests, and structural analysis.However, existing methods often rely on sparse outcome rewards or statically combine heterogeneous dense signals, even though syntax validity, executability, functional correctness, and structural organization describe different and progressively dependent programming capabilities. We propose DHRCL, a reinforcement learning framework with Dense Hierarchical Rewards and Curriculum Learning. DHRCL decomposes feedback into syntax validation, execution success, unit-test pass rate, and AST-based structural similarity, and organizes these signals through a three-stage Syntax, Execution, Pass & Structural curriculum. Stage duration is determined automatically from recent validation trends rather than manually specified capability thresholds. We further introduce stage-aware probability-based token credit redistribution. The mechanism follows a consolidation-to-refinement principle: it emphasizes established token patterns during syntax-oriented optimization, applies uniform propagation for non-local execution feedback, and allocates more credit or blame to less-established token decisions during final functional optimization. Under a unified Qwen3-8B and KodCode protocol, the experiments compare DHRCL with binary, pass-rate, reward-model-based, and verifiable dense-reward baselines. We further evaluate DHRCL across Qwen3-4B, Qwen3-8B, and Qwen3-14B backbones, showing that its advantage remains consistent as model capacity increases.

# DHRCL 论文总结

## 1. 论文的核心问题与整体含义（研究动机和背景）

- **背景**：强化学习（RL）是代码大语言模型（Code LLM）后训练的自然范式，因为生成的程序可以通过解析、执行、单元测试和结构分析获得自动可验证的反馈。
- **核心问题**：现有代码 RL 方法存在两类缺陷：
  - **稀疏奖励问题**：二元测试成功或单纯的通过率奖励在大多数样本失败时无法提供足够的梯度引导。
  - **静态组合问题**：将语法有效性、可执行性、功能正确性和结构组织等异质信号以静态权重混合，忽略了这些能力之间存在**逐级依赖**的前置关系（不能执行就谈不上功能正确，不能解析就谈不上执行）。
- **研究含义**：论文提出 DHRCL（Dense Hierarchical Rewards and Curriculum Learning），通过将反馈分解为语法→执行→功能&结构三个层级，并用课程学习（Curriculum Learning）按阶段组织优化重心，从而更有效地训练代码 LLM。

## 2. 论文提出的方法论

### 2.1 总体框架

DHRCL 包含两个耦合组件：
1. **密集分层奖励**（Dense Hierarchical Reward）：将代码反馈分解为四个互补信号。
2. **阶段感知课程学习**（Stage-aware Curriculum Learning）：将训练过程分为三阶段，并通过验证集趋势自动切换阶段；配套使用**阶段感知的概率型令牌信用重分配**。

### 2.2 密集分层奖励（四个奖励组件）

| 奖励组件 | 公式/定义 | 作用 |
|---|---|---|
| 语法验证率 `r_syntax` | 基于容错解析器（Tree-sitter）提取语法单元，以 token 长度为权重的有效单元比例加权平均 | 对局部格式良好的代码提供部分反馈 |
| 执行成功 `r_exec` | `I(execution success)` 指示函数 | 判断程序是否能无运行时错误、不超时、不超内存地执行 |
| 通过率 `r_pass` | `n_pass / n_test`（通过的测试用例比例） | 提供部分功能正确性的密集信号 |
| AST 结构相似度 `r_AST` | `Sim_AST(N(AST(y)), N(AST(y_ref)))`，基于归一化后 AST 的树编辑距离（TED） | 辅助性参考条件结构先验，不替代功能正确性 |

### 2.3 三阶段课程学习

三个阶段的奖励公式（`r_pass` 始终保留，确保功能正确性为最终目标）：

- **语法阶段（Syntax Stage）**：`r_i = r_pass,i + r_syntax,i + α_syntax·r_exec,i + α_syntax·r_AST,i`，其中 `α_syntax = batch内平均语法奖励`，作为能力依赖门控——语法弱时后继承的信号权重小。
- **执行阶段（Execution Stage）**：`r_i = r_pass,i + r_exec,i + α_exec·r_syntax,i + α_exec·r_AST,i`，`α_exec = batch内平均执行奖励`，重心转向整体程序的可运行性。
- **通过&结构阶段（Pass & Structural Stage）**：`r_i = r_pass,i + r_AST,i + α_pass·r_syntax,i + α_pass·r_exec,i`，`α_pass = batch内平均通过率`，主要优化功能正确性和结构先验。

### 2.4 基于趋势的自动阶段推进

- 不同于手动设定固定阈值，DHRCL 对当前阶段的**留出验证集主指标**（语法阶段监控语法奖励，执行阶段监控执行奖励，最终阶段监控验证 Pass@1）做线性趋势检验：
  - 收集至少 12 个验证观测后，用最近 8 个观测拟合线性模型 `m(t)=a_s+b_s·t+ϵ`。
  - 单侧检验 `H0: b_s ≤ 0 vs. H1: b_s > 0`。
  - 连续两次检验失败才触发阶段切换，并恢复该阶段最高验证指标的检查点。
- 最终阶段用同样规则做早停。

### 2.5 阶段感知概率型令牌信用重分配

对轨迹级优势 `A_i`，对每个 token 的梯度分配权重 `β_i,j`（三阶段遵循 "巩固→均匀→精炼" 原则）：

| 阶段 | 加权方式 | 公式 | 原理 |
|---|---|---|---|
| 语法阶段 | 置信度导向加权 | `β_conf = p_i,j / (1/|τ_i| Σ p_i,k)` | 加强已建立的令牌模式，正优势巩固有效模式，负优势抑制失败模式 |
| 执行阶段 | 均匀加权 | `β_exec = 1` | 运行有效性依赖非局部交互，token 概率无法可靠定位责任 |
| 通过&结构阶段 | 不确定性导向加权 | `β_unc = (1-p_i,j) / (1/|τ_i| Σ (1-p_i,k))` | 对尚未确立的低概率决策分配更多信用或责任 |

关键属性：三种加权在轨迹内均值均为 1，保持轨迹平均贡献不变，只改变梯度预算在 token 间的分配。

## 6. 论文的主要结论与发现

- **主对比**：DHRCL 在 Qwen3-8B 上平均 Pass@1 达 **50.3±0.2**，超过最强基线 VeRPO **1.1 个点**（95% 置信区间 [0.6, 1.5]），同时获得最高的语法准确率（92.8）、执行准确率（82.7）和 AST 相似度（0.68）。

- **消融结论**：
  - AST 奖励带来 +0.6 Pass@1 和明显的结构相似度提升（0.62→0.68）。
  - 趋势自适应课程优于静态联合和固定阶段切换。
  - "置信度→均匀→不确定性"的令牌加权顺序优于单一加权、无加权或反向顺序。
- **训练效率**：DHRCL 仅用 GRPO 55% 的 GPU 时长和 49% 的迭代次数达到目标验证性能，收敛效率显著更高。

- **错误类型分析**：DHRCL 将语法错误从 8.0%→4.8%，运行时错误从 9.7%→5.9%，超时从 4.8%→2.9%；**可执行但不正确的程序（Wrong Answer 36.1%）成为主要残余失败模式**。

## 7. 优点

- **奖励设计的层级性**：将编程能力按"语法→执行→功能→结构"的前置依赖关系组织，符合编程能力习得的天然顺序。
- **自动阶段推进**：基于验证趋势而非固定阈值，避免了强初始化立即推进、弱初始化卡住的问题；以"连续两次检验失败"降低对噪声音量点的敏感性，并在切换时恢复最佳检查点。
- **令牌信用重分配的创新性**："巩固→均匀→精炼"原则在理论上自洽：早期巩固已学会的模式、中期避免引入不可靠的局部偏差、后期精炼未稳定决策。三种加权都保持轨迹均值不变，只改分配，数学性质清晰。
- **实验受控良好**：统一协议下重新训练基线、三种子重复、配对 bootstrap 置信区间、详细的消融分解，显著提高了实验可信度。
- **评估多维度**：主指标 Pass@1 之外，还报告了语法/执行有效性、AST 相似度、运行时间和内存的诊断指标，对模型行为有更细颗粒度的刻画。
