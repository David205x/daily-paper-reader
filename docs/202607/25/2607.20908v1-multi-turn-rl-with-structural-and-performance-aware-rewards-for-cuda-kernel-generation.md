## 摘要
带可验证奖励的强化学习（RLVR）已成为增强大语言模型推理能力以优化代码生成的强大技术。然而，现有的RLVR方法主要依赖正确性和加速比等基于结果的信号，忽视了对于生成优化代码至关重要的程序性能关键结构属性。在这项工作中，我们提出了CudaPerf，一个反射式强化学习框架，它结合了可验证的执行奖励和源自并行化特征（例如，内存合并、占用率、算术强度和同步模式）的结构化代码感知奖励。CudaPerf分两个阶段运行：(1) 一个离线成对排序模块，通过对比学习区分强弱程序候选；(2) 一个在线RL训练阶段，通过统一的奖励信号联合优化正确性、性能和结构效率。为了进一步增强学习，CudaPerf利用执行反馈进行迭代优化，使生成的候选方案逐步改进。我们还引入了一个包含2.9k个C到CUDA和1k个PyTorch到CUDA程序的数据集，每个程序都配有多种输入配置和涵盖多种优化策略的多个CUDA实现。CudaPerf在多个基准测试上进行了评估，包括C到CUDA和PyTorch到CUDA的转换。实验结果表明，CudaPerf显著优于强基线方法，包括Qwen-3-32B（用于C到CUDA）和CUDA Agent（用于PyTorch到CUDA），在加速比上分别实现了高达5倍和3.32倍的提升，在正确性上分别实现了17%和7%的提升。

## Abstract
Reinforcement Learning with Verifiable Rewards (RLVR) has emerged as a powerful technique to enhance the reasoning capacity of LLMs for optimized code generation. However, existing RLVR approaches primarily rely on outcome-based signals such as correctness and speedup, overlooking performance-critical structural properties of programs that are essential for generating optimized code. In this work, we propose CudaPerf, a reflective RL framework that incorporates both verifiable execution rewards and structural code-aware rewards derived from parallelization features (e.g., memory coalescing, occupancy, Arithmatic Intensity, and synchronization patterns). CudaPerf operates in two stages: (1) an offline pairwise ranking module that learns to distinguish strong and weak program candidates via contrastive comparisons, and (2) an online RL training phase that jointly optimizes for correctness, performance, and structural efficiency through a unified reward signal. To further enhance learning, CudaPerf utilizes iterative refinement using execution feedback enabling progressive improvement of generated candidates. We also introduce a dataset comprising 2.9k C to CUDA and 1k PyTorch to CUDA programs, each paired with diverse input configurations and multiple CUDA implementations encompassing diverse optimization strategies. CudaPerf is evaluated across multiple benchmarks comprising both C to CUDA and PyTorch to CUDA transformations. Empirical findings suggest that CudaPerf significantly outperforms strong baselines, including Qwen-3-32B (for C to CUDA) and CUDA Agent (for PyTorch to CUDA) by achieving up to 5X & 3.32X improvements in speedup, and 17% & 7% improvements in correctness, respectively.

## 1. 核心问题与整体含义（研究动机和背景）

- **问题**：现有基于可验证奖励的强化学习（RLVR）方法在代码生成中主要依赖执行结果信号（如正确性、加速比），忽略了**代码的结构特性**（如内存合并、占用率、算术强度、同步模式等）。这些结构属性对高性能CUDA内核至关重要，但被现有RL方法所忽视。
- **目标**：提出一种能结合**执行反馈（可验证奖励）** 与**代码结构感知奖励**的强化学习框架，以生成更正确且更高性能的CUDA内核。
- **意义**：将程序优化从纯黑盒优化转向更可解释的白盒推理，利用并行化特征作为归纳偏置，提升模型对GPU性能关键因素的理解。

## 2. 方法论

### 核心思想
CudaPerf采用**两阶段训练**：  
1. **离线阶段**：训练一个轻量级MLP排序器，学习从CUDA代码特征映射到性能分数（结构奖励）。  
2. **在线阶段**：使用GRPO算法联合优化执行奖励与结构奖励，通过多轮迭代细化生成候选代码。

### 关键技术细节

#### （1）结构特征提取
- 针对CUDA程序提取11维特征向量：`[coal, ai, occ, div, xfer, atomics, syncthreads, kernels, tpb, gmem_access, ops]`。
- 特征归一化后，输入MLP排名器，输出标量结构奖励 `R_str = s_ψ(φ̂(y))`。

#### （2）成对排序模块
- 对每个任务，根据实测加速比将候选分为顶部和底部四分位，构建偏好对 `(y⁺, y⁻)`。
- 使用逻辑成对排序损失训练MLP：  
  `L_rank = E[log(1 + exp(-(s_ψ(φ̂(y⁺)) - s_ψ(φ̂(y⁻)))))]`。

#### （3）可验证执行奖励
- 包含四项：编译惩罚、正确性惩罚（测试通过率）、性能奖励（对数缩放加速比）、稳定性惩罚（运行时间变异系数）。
- 最终可验证奖励 `R_ver` 根据编译和测试结果动态组合。

#### （4）在线RL训练（GRPO）
- 策略模型基于Qwen-3-32B，使用QLoRA微调。
- 每个训练样本生成16个候选，计算每个候选的复合奖励 `r_i = R_ver(i) + R_str(i)`。
- 组内归一化后，计算GRPO损失（截断参数ε=0.2，KL散度权重β=0）。

#### （5）多轮迭代细化
- 每轮最多5次细化，提供编译错误、失败用例、加速比及结构特征值作为结构化反馈。
- 历史反馈由LLM总结后嵌入提示，防止上下文膨胀。

## 6. 主要结论与发现

1. **性能大幅领先**：CudaPerf在所有基准上显著优于最强基线。
   - C→CUDA：自建数据集上正确率89%（+17% vs Qwen-3-32B），加速比11.02X（+4.82X）。BabelTower上正确率94%（与QiMeng-MuPa持平），加速比9.02X（+3.01X）。
   - PyTorch→CUDA：KernelBench上正确率93%（+7% vs CUDA Agent），加速比6.41X（+3.32X）。
2. **结构奖励与执行奖励互补**：仅用结构奖励时性能显著下降；仅用执行奖励时也不及两者结合（表3）。
3. **模型规模影响**：基座模型越大，效果越好（8B→14B→32B）。
4. **多轮细化有效**：通过执行反馈迭代改进，进一步提升正确性和性能。

## 7. 优点

- **创新奖励设计**：首次将CUDA并行化特征（内存合并、算术强度等）作为结构化奖励引入RL，提供可解释的归纳偏置。
- **两阶段训练高效**：先训练轻量排序器，再在RL中混合奖励，避免在线执行开销过大。
- **多轮迭代细化**：利用编译信息和结构化特征反馈，逐步修正错误，提升收敛质量。
- **数据集贡献**：构建了高质量多候选CUDA数据集（2.9k+1k），便于后续研究。
- **实验规范**：严格按pass@标准报告，控制随机种子和多次执行取中位数，消融实验完整。

## 8. 不足与局限

- **计算开销大**：训练需要反复编译和运行CUDA程序，总训练时间达3-4天（双A100），扩展到大模型或大规模数据时可能受限。
- **依赖固定特征集**：结构特征基于现有GPU性能模型（如占用率、合并等），可能无法捕捉新型优化策略（如tensor core、warp-level primitives）。
- **系统偏差风险**：仅针对NVIDIA GPU测试，结论可能不直接迁移到AMD或Intel GPU。
- **模型泛化性**：实验仅用Qwen-3系列，未验证其他LLM作为基座的效果；且仅在32B及以下规模测试。
- **奖励设计假设**：使用对数加速比和固定阈值，可能对极端情况（严重错误或极大加速）不够鲁棒。
- **缺乏生产环境验证**：数据集多为教学型OJ问题，真实HPC应用（如大规模矩阵运算、多GPU通信）未经测试。
