## 摘要
针对不同成本-质量权衡的大语言模型（LLM）进行路由选择已成为企业AI的基本部署特性。现有的路由器主要为每次LLM调用独立做出路由决策。然而，代理式应用以长期工作流的形式执行，其质量仅由延迟的任务级结果决定。这种不匹配使得逐调用路由器无法正确地将反馈归因于单个路由决策。为了缓解这一问题，我们提出了TRACE-Router，一种任务级路由框架，将路由与监督单元对齐。TRACE-Router使用上下文赌博机在任务接纳时一次性为每个任务分配模型，将所有后续LLM调用绑定到所选后端，并利用任务的终端奖励更新其策略，同时考虑准确性和延迟。通过利用延迟的任务反馈，TRACE-Router学习适应工作负载的路由策略，同时避免显式的任务复杂性估计。在三个代理式基准测试中，TRACE-Router持续改善了准确性-延迟权衡，实现了非支配的帕累托前沿点。在tau2-Bench上，它比个体模型之间的延迟匹配插值高出7-8个准确率点；而在Terminal-Bench上，它相比最强的单一模型基线实现了7.1个更高的准确率点，同时延迟降低了36%。

## Abstract
Routing to select large language models (LLMs) with different cost-quality trade-offs has become a fundamental deployment feature of enterprise AI. Existing routers, primarily make independent routing decisions for each LLM call. However, agentic applications execute as long-horizon workflows whose quality is determined only by a delayed, task-level outcome. This mismatch prevents per-call routers from correctly attributing feedback to individual routing decisions. Towards mitigating this, we present TRACE-Router, a task-level routing framework that aligns routing with the unit of supervision. TRACE-Router assigns each task to a model once at admission using a contextual bandit, pins all subsequent LLM calls to the selected backend, and updates its policy using the task's terminal reward, jointly accounting for accuracy and latency. By leveraging delayed task feedback, TRACE-Router learns routing policies that adapt to the workload while avoiding explicit task-complexity estimation. Across three agentic benchmarks, TRACE-Router consistently improves the accuracy-latency trade-off, achieving non-dominated Pareto frontier points. On tau2-Bench, it outperforms latency-matched interpolation between individual models by 7-8 accuracy points, while on Terminal-Bench it achieves 7.1 higher accuracy points than the strongest single model baseline with 36% lower latency.

# TRACE-ROUTER: 任务一致且自适应在线路由 — 论文详细中文总结

## 1. 核心问题与整体含义（研究动机与背景）

- **问题**：现有大语言模型（LLM）路由器大多按**每次调用（per-call）** 独立决策。然而在智能体（Agentic AI）工作流中，一个任务包含多次 LLM 调用、工具调用和环境交互，任务质量只由**最终（延迟的）任务级结果**决定。逐调用路由无法将延迟反馈正确归因到各次决策，容易导致中途切换模型破坏状态、反馈信号碎裂。
- **意义**：作者提出路由的粒度应与**反馈的粒度**对齐——即任务级路由。TRACE-Router 在任务进入时用上下文赌博机一次选定后端模型，后续所有调用固定，等任务结束后用终端奖励更新策略。这一设计从根本上解决了反馈归因问题，并能适应工作负载变化，无需显式估计任务复杂度。

## 2. 方法论：核心思想、关键技术细节

### 核心思想
- **任务一致性路由**：一个任务的所有 LLM 请求绑定到同一个后端模型。维护一个活动任务表 `A`，将任务标识符 `κ_t` 映射到上下文 `c_t` 和模型 `m_t`。首次请求时确定映射（通过上下文赌博机），后续请求直接复用。
- **上下文条件模型选择**：用简单分类器（本文为正则表达式）将任务初始描述符映射到有限个离散上下文（EASY、MEDIUM、HARD）。每个上下文维护一个独立的赌博机。
- **冷启动上下文 UCB**：每个上下文-模型对初始化为零（拉取计数 `N` 和奖励和 `S`）。前 `k|M|` 个任务（`k=1`，两个模型时每上下文2个任务）用轮询方式强制探索。之后按照 UCB 公式选择模型：
  - `m_t = argmax_m [ μ̂_{c,m} + sqrt(2 log(1/δ) / N_{c,m}) ]`，其中 `δ=0.1` 为固定置信参数。
- **延迟信用分配**：任务结束后，评估器返回分级准确率 `a_{t,m}`，延迟跟踪器返回端到端延迟 `ℓ_{t,m}`，合并为奖励 `r(α) = (1−α)a_{t,m} − α·min(ℓ_{t,m}/ℓ_0,1)`，`α∈[0,1]` 为偏好参数。更新时仅修改该任务所属上下文-模型对的统计量。
- **可替换组件**：上下文分类器、赌博机策略（UCB、ε-贪心、汤普森采样）、奖励参数 `α` 均可根据部署需求替换。

### 算法流程（文字说明）
1. 新任务到达，提取初始描述符，通过上下文函数得到上下文 `c`。
2. 根据上下文 `c` 对应的赌博机，若处于冷启动阶段则轮询选择模型，否则按 UCB 选择模型 `m`。
3. 记录 `(c, m)` 到活动任务表。之后该任务的所有 LLM 请求都路由到该模型。
4. 任务执行完成后，获得准确率和端到端延迟，计算奖励 `r`。
5. 查找活动任务表，更新对应上下文-模型对的 `N` 和 `S`，并从表移除该任务。
6. 后续任务使用更新后的统计量。多个 α 值独立维护策略状态，互不影响。

## 6. 主要结论与发现

1. **TRACE-Router 持续占据准确率-延迟帕累托前沿内部**：在 τ2-Bench 平均上，三个操作点（55.2%、57.6%、61.2% 准确率，延迟 25.4-26.4 秒）均优于所有启发式和学习的基线，且比延迟匹配的随机混合高 7-8 个准确率点。
2. **超越单个大模型**：在 Terminal-Bench 上，TRACE-Router（α=0.75）解决 46.8% 任务（172 秒），大模型（27B）为 39.7%（270 秒）——准确率高 7.1 点，延迟低 36%。证明了路由不仅为妥协，而是严格优于任一单一模型。
3. **上下文条件的重要性**：无上下文的全局策略无法达到前沿内部，因为混合了冲突的模型偏好（如小模型在零售域可用、电信域不可用）。
4. **冷启动优于热启动**：冷启动（轮询 6 个任务后 UCB）在准确率上几乎持平热启动，但延迟显著更低（热启动倾向于保守选择大模型）。
5. **UCB 稳定性最好**：相比 ε-贪心和汤普森采样，UCB 在三个基准上的最佳参数区间一致（δ∈[0.5,0.8]），而 ε-贪心的最佳 ε 随数据集变化大，不适合在线自适应。
6. **四模型扩展中仍有效**：TRACE-Router 快速识别超时或低效模型，转向较好模型，显著优于语义和复杂度路由器。

## 7. 优点

- **任务级路由思想创新**：对齐反馈单位，解决了长期智能体任务中累积反馈归因的根本问题。
- **完全在线、无需离线训练**：只依赖任务执行结果，无需预标注路由数据或复杂性估计，易于部署和适应变化。
- **轻量级上下文分区**：使用简单正则（无模型调用、无嵌入、无训练数据）仍然取得显著收益，且可替换为更精细的分类器。
- **全面且公平的实验**：对比多种基线、消融设计严谨，使用了延迟匹配随机混合作为公平参考，并公开离线回放验证一致性。
- **实用性强**：有明确的冷启动开销（6 个任务），奖励函数可调（α 控制偏好），便于实际部署。
