## 摘要
根据不同的成本-质量权衡选择大型语言模型（LLM）的路由已成为企业AI的基础部署特性。现有路由器主要对每次LLM调用做出独立路由决策。然而，智能体应用作为长期工作流执行，其质量仅由延迟的任务级结果决定。这种不匹配使得每次调用的路由器无法正确地将反馈归因于单个路由决策。为解决此问题，我们提出TRACE-Router，一种将路由与监督单元对齐的任务级路由框架。TRACE-Router在任务进入时使用上下文赌博机一次性将任务分配给某个模型，将所有后续LLM调用固定到所选后端，并利用任务的终端奖励更新策略，同时考虑准确性和延迟。通过利用延迟的任务反馈，TRACE-Router学习适应工作负载的路由策略，同时避免显式的任务复杂度估计。在三个智能体基准测试中，TRACE-Router持续改善准确性-延迟权衡，达到非支配帕累托前沿点。在tau2-Bench上，它比延迟匹配的单个模型插值高出7-8个准确率点，而在Terminal-Bench上，它比最强的单模型基线高出7.1个准确率点，且延迟降低36%。

## Abstract
Routing to select large language models (LLMs) with different cost-quality trade-offs has become a fundamental deployment feature of enterprise AI. Existing routers, primarily make independent routing decisions for each LLM call. However, agentic applications execute as long-horizon workflows whose quality is determined only by a delayed, task-level outcome. This mismatch prevents per-call routers from correctly attributing feedback to individual routing decisions. Towards mitigating this, we present TRACE-Router, a task-level routing framework that aligns routing with the unit of supervision. TRACE-Router assigns each task to a model once at admission using a contextual bandit, pins all subsequent LLM calls to the selected backend, and updates its policy using the task's terminal reward, jointly accounting for accuracy and latency. By leveraging delayed task feedback, TRACE-Router learns routing policies that adapt to the workload while avoiding explicit task-complexity estimation. Across three agentic benchmarks, TRACE-Router consistently improves the accuracy-latency trade-off, achieving non-dominated Pareto frontier points. On tau2-Bench, it outperforms latency-matched interpolation between individual models by 7-8 accuracy points, while on Terminal-Bench it achieves 7.1 higher accuracy points than the strongest single model baseline with 36% lower latency.

## 2. 方法论

### 核心思想
- **任务一致性路由（Task-Consistent Routing）**：每个任务进入时，路由器只做一次模型选择，随后该任务的所有 LLM 请求都固定到同一后端，并携带持久化的任务标识符 κ<sub>t</sub>，存储在活动任务表 A 中。
- **上下文条件化模型选择（Context-Conditioned Model Selection）**：使用粗粒度的上下文分类器（基于正则表达式和长度阈值，分为 Easy/Medium/Hard 三级），为每个上下文维护独立的赌博机（Bandit）实例，避免全局策略混淆不同难度下的模型偏好。
- **冷启动上下文 UCB 策略（Cold-Start Contextual UCB）**：每个上下文内，对每个后端先进行 k=1 次轮询强制拉取，之后使用 UCB 选择上置信界最大的后端：m<sub>t</sub> = argmax<sub>m</sub> [ μ̂<sub>c,m</sub> + √(2 log(1/δ) / N<sub>c,m</sub>) ]，其中 δ 为探索强度（默认 0.1）。
- **延迟信用分配与奖励设计**：任务完成后，将标量化的准确率 a<sub>t,m</sub> 和归一化延迟 ℓ̃<sub>t,m</sub> 通过参数 α 组合为单步奖励 r<sup>(α)</sup><sub>t,m</sub> = (1-α) a<sub>t,m</sub> - α ℓ̃<sub>t,m</sub>，用于更新对应上下文-后端的统计量。

### 算法流程简述
1. 任务 t 进入，代理框架附加持久标识 κ<sub>t</sub>。
2. 检查 κ<sub>t</sub> 是否已在活动表 A 中：  
   - 若在，则复用已有后端分配；  
   - 若不在，则用上下文函数 g(x<sub>t</sub>) 计算上下文 c<sub>t</sub>，从该上下文的赌博机 π<sub>c<sub>t</sub></sub> 中采样一个后端 m<sub>t</sub>，记录 (c<sub>t</sub>, m<sub>t</sub>) 到 A。

5. 从 A 中移除已完成任务。

## 6. 主要结论与发现

1. **TRACE-Router 在准确率-延迟前沿上占据内部位置**，在所有三个基准上均优于所有学习和启发式基线，并优于延迟匹配的随机混合（在 τ²-Bench 上高出 7–8 个准确率点）。
2. **上下文条件化是必要的**：无上下文变体在部分 α 点上被支配，而上下文变体能保持前沿位置。
3. **冷启动优于热启动**：热启动虽然准确率相当，但系统性偏向慢模型，导致延迟位置更高。
4. **UCB 在探索强度稳定性上优于 ε-greedy 和 Thompson sampling**：UCB 的最优参数 δ 在三个基准上稳定在 0.5–0.8，而 ε-greedy 的最优 ε 随数据集变化，不可部署。
5. **在 Terminal-Bench 上，路由严格支配两个单模型**：TRACE-Router 以 36% 更低的延迟实现了比大模型高 7.1 个准确率点，接近准确率预言机。

## 7. 优点

- **对齐路由粒度与反馈粒度**：首次提出任务级路由在智能体工作流中的必要性，克服了请求级路由信用分配困难的根本问题。
- **在线自适应**：无需离线训练数据，仅从任务完成后的结果中学习，能适应不断变化的工作负载。
- **轻量级上下文分类**：使用无需模型调用的正则表达式分类器，边缘开销极低，且证明合理。
- **全面的消融与敏感性分析**：系统性地设计了多个消融实验（上下文、初始化、策略选择、模型池扩展），结果可靠，并提供了 80 种子的统计置信区间。
- **严格的前沿分析**：采用延迟匹配随机混合作为基线，避免了“出现在前沿即可”的虚假优势验证。
- **四模型扩展验证了可扩展性**：对更多候选模型时，自适应探索能力优势更加显著。

## 8. 不足与局限

- **任务数量有限**：Terminal-Bench 仅 48 个任务，使得单个任务的权重过大（2.1 点 / 任务），可能放大随机性影响。
