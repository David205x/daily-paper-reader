## 摘要
多轮信息寻求对话既需要多跳推理，也需要跨轮次的长距离依赖追踪。然而，现有的RAG系统通常将对话记忆表示为原始对话历史、重写查询或非结构化摘要，这使得难以恢复后续查询所需的具体先前推理步骤和证据。我们的关键见解是将对话记忆与检索对齐，通过将对话上下文表示为子问题级别的推理痕迹。基于这一见解，我们引入了MuMu-QA，一个带有显式跨轮子问题依赖注释的多轮多跳RAG基准，以及CMT-RAG，一种针对该场景的互补记忆框架。在每一轮中，CMT-RAG采用状态空间痕迹生成器，其循环状态作为运行时记忆，以整合近期对话上下文并将当前查询分解为包含检索导向子问题和早期痕迹依赖的结构化痕迹草稿。然后，它用检索到的证据来验证这些草稿，并将它们作为持久记忆痕迹存储在会话级DAG中，使未来轮次能够高效地恢复相关的先前推理和证据。在MuMu-QA和语料级RAG基准上的实验表明，CMT-RAG在答案准确性上 consistently 优于五类RAG基线。

## Abstract
Multi-turn information-seeking conversations require both multi-hop reasoning and long-range dependency tracking across turns. However, existing RAG systems typically represent conversational memory as raw dialogue history, rewritten queries, or unstructured summaries, making it difficult to recover the specific prior reasoning steps and evidence required for follow-up queries. Our key insight is to align conversational memory with retrieval by representing dialogue context as sub-question-level reasoning traces. Building on this insight, we introduce MuMu-QA, a benchmark for multi-turn multi-hop RAG with explicit cross-turn sub-question dependency annotations, and CMT-RAG, a complementary memory framework for this setting. At each turn, CMT-RAG employs a state-space trace generator, whose recurrent state serves as runtime memory, to incorporate recent conversational context and decompose the current query into structured trace drafts containing retrieval-oriented sub-questions and dependencies on earlier traces. It then grounds these drafts with retrieved evidence and stores them as persistent memory traces in a session-level DAG, enabling future turns to efficiently recover relevant prior reasoning and evidence. Experiments on MuMu-QA and corpus-level RAG benchmarks show that CMT-RAG consistently outperforms five categories of RAG baselines in answer accuracy.

## 论文总结：CMT-RAG——面向多轮多跳RAG的互补记忆痕迹

### 1. 核心问题与整体含义（研究动机与背景）

- **问题背景**：多轮信息寻求对话要求系统同时具备多跳推理能力（将复杂查询分解为多个相互依赖的子问题）和跨轮次长距离依赖追踪能力（后续问题常依赖先前轮次建立的实体或推理结果）。
- **现有方法的不足**：现有RAG系统对对话记忆的表示方式存在根本性不匹配——
  - **原始对话历史**：过长，检索效率低，且难以精准定位先前的推理步骤；
  - **查询重写**（如ConvSearch-R1、ChatQA）：将上下文依赖问题转为独立查询，但将依赖链压缩进单一查询，丢失了中间检索目标；
  - **非结构化摘要**：无法恢复具体的子问题依赖关系和证据。
- **核心差距**：检索器需要子问题级别的记忆（即知道“当前子问题依赖哪些先前子问题及其证据”），而现有系统只维护轮次级别的上下文。
- **作者核心洞察**：将对话记忆与检索机制对齐——把对话上下文表示为**子问题级别的推理痕迹（sub-question-level reasoning traces）**，使记忆单元与检索单元成为同一持久化对象。

### 2. 方法论：核心思想、关键技术细节与算法流程

#### 2.1 核心思想：互补记忆痕迹

CMT-RAG 提出双通道互补记忆架构：

1. **SSM循环状态（运行时记忆）**：负责局部话语连续性与近期上下文追踪；
2. **会话级Trace DAG（持久记忆）**：负责长距离依赖解析与证据复用。

#### 2.2 任务形式化

- 对话定义为有序的用户轮次序列，系统需为每轮生成答案。
- 每个推理痕迹（Trace）绑定四个字段：
  \[\mathcal{T}_k = \langle q^{\text{sub}}_k, kw_k, \text{deps}(k), \text{para\_ids}_k \rangle\]
  - \(q^{\text{sub}}_k\)：已解析的子问题（供读取器和检索器消费）；
  - \(kw_k\)：痕迹DAG的词法查找关键词；
  - \(\text{deps}(k)\)：前置痕迹依赖列表；
  - \(\text{para\_ids}_k\)：为该子问题直接检索到的段落标识符。
- 整个会话被形式化为**痕迹有向无环图（Trace DAG）**：\(\mathcal{G} = (\mathcal{V}, E_\mathcal{G})\)，节点为带答案的痕迹，边表示依赖关系。

#### 2.3 体系结构：四阶段流程

1. **痕迹生成（Trace Generation）**：基于Mamba-2-2.7B的状态空间模型（SSM），通过LoRA微调和DPO训练，接收当前查询和新状态，生成结构化痕迹草稿 \(\{T^{\text{draft}}_k\} = \langle q^{\text{decom}}_k, kw_k, \text{deps}(k)\rangle\)，并更新隐藏状态。
2. **引用消解（Reference Resolution）**：通过预测的依赖标识符遍历Trace DAG，将答案引用令牌 \( [A_i] \) 替换为实际前置答案，生成解析后的子问题 \(q^{\text{sub}}_k\)。
3. **证据检索与痕迹更新**：
   - 依赖边直接恢复前置痕迹的证据（\(P_{\text{prior}}\)）；
   - 痕迹关键词通过轻量词法匹配检索额外历史痕迹；
   - 解析后的子问题通过DRAGON稠密检索器（top-5）获取新证据（\(P_{\text{local}}\)）；
   - 合并去重后形成读取器的完整上下文 \(P_k = P_{\text{local}} \cup P_{\text{prior}}\)。
4. **问答（Question Answering）**：无状态读取器仅使用组装好的证据回答每个解析子问题，随后聚合生成最终答案；完整痕迹及其子答案被追加至DAG。

#### 2.4 训练策略

- **三阶段课程式SFT**：
  - 阶段1：单轮示例，学习痕迹语法和基本分解结构；
  - 阶段2：短多轮对话；
  - 阶段3：长对话，同时回放早期样本防止遗忘。
- **DPO偏好优化**：通过固定检索-读取管道执行候选痕迹，使用组合奖励 \(R(\tau; c) = F_{\text{final}}(\tau) + \gamma F_{\text{sub}}(\tau)\) 排名，从中构建偏好对（\(\beta=0.05\)，\(\gamma=0.2\)）。

#### 2.5 基准构建：MuMu-QA

- 基于MuSiQue的子问题分解、中间答案和支持段落构建。
- 两种图级合成算子：
  - **子问题重定位（Sub-question Relocation）**：将子问题移至后续轮次，制造跨轮依赖；
  - **图拼接（Graph Splicing）**：通过桥接答案连接两条推理链。
- 提供全局子问题ID、痕迹关键词、依赖边、黄金支持段落ID和全DAG监督。
- 分为短对话（3-7轮）、长对话（6-32轮）和超长对话（33-67轮）三种长度区间。
