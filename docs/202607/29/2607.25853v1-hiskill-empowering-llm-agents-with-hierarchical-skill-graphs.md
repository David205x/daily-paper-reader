## 摘要
技能已成为使大语言模型（LLM）智能体在长周期交互任务中复用过去经验的重要抽象。然而，现有的轨迹转技能方法通常产生扁平的、高层次文本技能集合，这些技能被独立存储和检索，导致技能之间的关系未被充分利用，且在高层次技能与可执行动作之间存在鸿沟。在本文中，我们提出HiSkill，一种层次化技能图框架，它将交互轨迹组织成一个有向图，包含技能节点、原子操作节点和类型化边。具体来说，该图将可复用的高层次技能与可执行动作模板相连接，同时捕捉它们之间的分解、时间转换、兼容性、支持与恢复关系。在推理时，HiSkill检索一个紧凑的任务相关子图，并执行子图引导的任务执行，其中符号任务状态、活跃技能和检索到的子图引导LLM智能体迭代地切换技能、选择原子操作并实例化可执行动作。在三个交互环境上的实验表明，HiSkill在减少推理token消耗的同时，优于最先进的基线方法，证明了通过层次化技能图桥接高层次技能与可执行动作落地的有效性。我们的数据和代码可在 https://github.com/BUPT-GAMMA/HiSkill 获取。

## Abstract
Skills have become an important abstraction for enabling large language model (LLM) agents to reuse past experience in long-horizon interactive tasks. However, existing trajectory-to-skill methods often produce flat collections of high-level textual skills that are stored and retrieved independently, leaving skill relations underutilized and maintaining a gap between high-level skills and executable actions. In this paper, we propose HiSkill, a hierarchical skill graph framework that organizes interaction trajectories into a directed graph with skill nodes, AtomicOp nodes, and typed edges. Specifically, the graph connects reusable high-level skills with executable action templates, while also capturing decomposition, temporal transition, compatibility, support, and recovery relations among them. At inference time, HiSkill retrieves a compact task-relevant subgraph and performs subgraph-guided task execution, where a symbolic task state, an active skill, and the retrieved subgraph guide the LLM agent to switch skills, select AtomicOps, and ground executable actions iteratively. Experiments on three interactive environments show that HiSkill outperforms state-of-the-art baselines while reducing inference token consumption, demonstrating the effectiveness of bridging high-level skills and executable action grounding through a hierarchical skill graph. Our data and code is available at https://github.com/BUPT-GAMMA/HiSkill.

## 一、论文的核心问题与整体含义（研究动机和背景）

- **核心问题**：现有LLM智能体的技能学习方法（如从交互轨迹中提取技能）通常产生**扁平、独立的高层文本技能集合**，忽略技能间的内在关系（如分解、时间顺序、兼容性、支持与恢复），且高层技能描述与可执行的低层动作之间存在**鸿沟**——模型难以从文本描述中直接推断出具体动作参数和执行时机。
- **研究动机**：为克服上述局限，论文提出一种**层次化技能图（Hierarchical Skill Graph）**，将轨迹中的高层技能与可执行动作模板（AtomicOp）显式连接，并通过多种类型边编码执行关系，从而在推理时利用图结构引导LLM智能体更有效地完成长周期交互任务。

## 二、论文提出的方法论

### 核心思想
- 构建一个包含两种节点（**技能节点**、**原子操作节点AtomicOp**）和五种类型有向边（`decomposes to`、`can follow`、`compatible with`、`supports`、`recovers with`）的层次化有向图。
- 推理时：检索与当前任务相关的紧凑子图，并通过**符号任务状态**、**活跃技能**与子图联合引导 LLM 进行技能切换、AtomicOp 选择与动作落地。

### 关键技术细节流程

1. **层次化技能图构建（离线）**
   - **AtomicOp提取**：对原始动作进行模式归一化（将任务特定实体替换为占位符），去重合并得到可执行动作模板集合 \(V_O\)。
   - **技能发现**：从成功轨迹的 AtomicOp 序列中挖掘频繁子序列，每个保留模式抽象为一个技能节点 \(V_S\)，附带有序 AtomicOp 序列、适用状态、预期状态变化、参数候选、失败提示等结构化元数据。LLM 仅用于润色文本字段，不改变原子结构。
   - **类型化边归纳**：
     - `decomposes to`：技能→其包含的 AtomicOp。
     - `can follow`：技能间或AtomicOp间的时序转移（基于成功轨迹中相邻/有序共现计数）。
     - `compatible with`：技能间无状态冲突的共现关系（对称边）。
     - `supports`：辅助AtomicOp→技能，当技能前置条件缺失时提供支持（基于轨迹片段中AtomicOp后状态与技能前状态的重叠度）。
     - `recovers with`：恢复技能/AtomicOp→失败或停滞节点（从失败轨迹中提取重复无效动作后的有效动作，或基于语义/状态匹配）。

2. **任务相关子图检索（推理时）**
   - 构造查询 \(x_q\)（任务描述+初始观察），对每个节点 \(v\) 计算**混合检索分数**：\(\text{score}(v|q) = \lambda \cdot \text{Dense}(x_q, d_v) + (1-\lambda) \cdot \text{Sparse}(x_q, d_v)\)，分别对技能和AtomicOp节点排序，各取Top-K作为种子节点。
   - **图扩充（Graph Hydration）**：对种子节点进行一跳扩展，保留分解边（向下添加AtomicOp）和其他类型边的逆向邻居，形成紧凑子图 \(G_q\)。

3. **子图引导的任务执行（推理时）**
   - 维护**符号任务状态** \(z_t\)：键值对记录进度、对象、位置、已访问实体、缺失条件等。
   - **技能切换**：初始由LLM从种子技能中选一个活跃技能；当技能完成时，通过`can follow`或`compatible with`选择后继；当执行卡住或连续失败时，通过`recovers with`切换到恢复技能。
   - **AtomicOp选择**：默认取当前技能的下一个待执行AtomicOp；缺失前置条件时选支持AtomicOp（`supports`）；卡住或失败时选恢复AtomicOp（`recovers with`）；无合适选项时允许LLM直接生成动作。
   - **动作落地**：对选中的AtomicOp模板，利用任务描述、当前观察、状态和参数候选实例化为具体可执行动作。

## 六、论文的主要结论与发现

1. **性能优势**：HiSkill在三个环境的所有split上均取得最优或并列最优结果。与最强基线相比，**成功率平均相对提升17.33%**，得分平均相对提升22.95%。
2. **推理效率**：在所有数据集上，HiSkill的**推理token消耗最低**，比最低token基线还少61%~94%，说明性能提升来自紧凑的结构化子图而非长文本注入。
3. **组件贡献**：消融实验证实AtomicOp节点、类型化边、支持/恢复边、任务状态均显著贡献最终效果。组件互换实验表明**图表示与运行时机制需联合设计**，单独替换一方无法达到完整性能。
4. **对骨干模型鲁棒**：在Gemini-2.5-Pro和GPT-5.2-Codex上趋势一致，效果稳定。

## 七、优点（方法与实验亮点）

- **结构化层次设计**：将高层技能与低层可执行动作显式连接，且通过多种类型边编码执行关系，既保留了抽象能力又提供了具体落地路径。
- **高效检索与推理**：混合检索+图扩充得到紧凑子图，推理时仅需少量LLM调用（每步选择技能或AtomicOp），大幅降低token消耗。
- **符号状态驱动**：显式维护任务状态（完成度、缺失条件等），结合图关系实现动态技能切换和异常恢复，减少LLM幻觉和重复错误。
- **自动构建无需人工**：图结构完全从轨迹统计中归纳，LLM仅用于文本润色，可扩展性强。
- **完备的消融与组件互换实验**：不仅拆解了自身模块，还验证了与现有方法（GoS）的图与执行机制的兼容性，证明了设计的一体化必要性。
